# 0-1 背包（0/1 Knapsack）深度解析：从暴力搜索到一维滚动的思维演进

> **一句话总纲**：0-1 背包是动态规划世界的"Hello World"，但它绝不简单——**它把"每件物品选或不选"这个 `2^n` 的指数决策树，通过"记住重复计算的子问题"压缩成 `O(nV)` 的二维表格，再通过"倒序滚动"把表格压成一行。** 读懂 0-1 背包四种写法（回溯 → 记忆化 → 二维递推 → 一维滚动）之间的演进关系，就读懂了整个动态规划的核心方法论：**如何定义状态、如何写转移、如何优化空间。**

本文沿着"**为什么需要它 → 四种写法如何一步步进化 → 转移方程与空间优化的数学原理 → 有哪些变体 → 怎么一眼看出该用背包模型**"这条主线，把 0-1 背包彻底讲透。

## 一、起源与设计哲学

### 1.1 它到底为了解决什么问题？

**0-1 背包的原型**：有一个容量为 `V` 的背包，和 `N` 件物品，第 `i` 件物品费用（重量）为 `Cᵢ`、价值为 `Wᵢ`。**每件物品只有"选"或"不选"两种状态（这就是"0-1"的由来）**，求在总费用不超过 `V` 的前提下，能装入的最大总价值。

这个模型抽象了现实中一大类"**在资源约束下做离散取舍以最大化收益**"的问题：预算有限选项目、时间有限选任务、流量有限选内容……凡是"**每个候选不可分割、只能整个要或整个不要**"的最优化问题，几乎都能归约到 0-1 背包。

### 1.2 为什么贪心在这里失效？—— DP 登场的必然性

一个自然的想法是**贪心**：按"性价比 `Wᵢ/Cᵢ`"从高到低装。但这在 0-1 背包上**会失败**：

> 反例：容量 `V=10`，物品 `(重6,值10)、(重5,值9)、(重5,值9)`。按性价比贪心先选第一件（性价比 10/6 最高），剩余容量 4 装不下任何东西，总值 **10**；但最优解是后两件，总值 **18**。

**根因**：物品**不可切分**，破坏了"贪心选择性质"。当下看起来最优的选择（性价比最高），会挤占后续更优组合的空间，且**无法反悔**。既然局部最优拼不出全局最优，就必须**考察所有可能的组合**——但直接枚举是 `2^n` 的指数爆炸。

**动态规划的核心洞察**登场了：

> **虽然组合有 `2^n` 种，但它们在计算过程中会反复遇到相同的"子问题"（考虑前 `i` 件物品、剩余容量 `v` 时的最优值）。只要把每个子问题的答案记下来，就能把指数级的重复计算压缩成多项式级。**

这就是 0-1 背包乃至整个 DP 成立的两大前提：

- **最优子结构**：原问题的最优解，由子问题的最优解组合而成。
- **重叠子问题**：递归求解时，同一个子问题会被反复计算——正是"记忆化"能生效的关键（这也是 DP 区别于贪心的地方，贪心不具备重叠子问题特征）。

### 1.3 设计哲学：用"空间"换"时间"

0-1 背包的整个演进史，本质是一场**空间与时间的博弈**：

- 回溯法：**时间 `O(2^n)`、空间 `O(n)`**（只有递归栈）——时间差到不可用。
- 记忆化 / 递推：**时间 `O(nV)`、空间 `O(nV)`**——用一张表格换来指数级加速。
- 一维滚动：**时间 `O(nV)`、空间 `O(V)`**——再把表格压成一行。

这条主线完美诠释了 DP 的方法论：**先想清楚"状态是什么"，再想"状态怎么转移"，最后想"表格能不能压缩"。**

## 二、四种写法的思维演进（核心）

参考代码给出了 0-1 背包的**四种实现**，它们不是并列的，而是**层层递进、互为因果**的一条思维链。理解这条链，胜过背下任何一个模板。

```text
① 回溯(暴力枚举)  ──发现大量重复子问题──▶  ② 记忆化搜索(自顶向下)
                                              │ 改写递归为循环
                                              ▼
④ 一维滚动数组  ◀──倒序压缩掉物品维度──  ③ 二维递推(自底向上)
```

### 2.1 第一站：回溯法 —— 最朴素的"选或不选"

回溯直接翻译问题定义：对每件物品，分"选"和"不选"两条路径递归到底，用可行性约束剪枝。

```java
public class ZeroOne_backtrack implements ZeroOnePack {
    int ans;
    public int backPack(int[] C, int[] W, int V) {
        ans = 0;
        backtrack(0, C, W, V, 0, 0);
        return ans;
    }
    // i: 当前物品下标; cw: 已用容量; cv: 已获价值
    public void backtrack(int i, int[] C, int[] W, int V, int cw, int cv) {
        if (cw > V) return;                    // 剪枝：超重
        if (i == C.length) {                   // 所有物品决策完毕
            if (cv > ans) ans = cv;
            return;
        }
        if (cw + C[i] <= V) {                  // 可行性约束：能装下才选
            backtrack(i + 1, C, W, V, cw + C[i], cv + W[i]);  // 选第 i 件
        }
        backtrack(i + 1, C, W, V, cw, cv);     // 不选第 i 件
    }
}
```

- **优点**：最直观，直接对应"每件物品选或不选"的二叉决策树。
- **致命缺点**：时间复杂度 `O(2^n)`。**关键观察——不同的"选择路径"会到达完全相同的状态 `(i, 剩余容量)`，却被反复重算。** 这正是优化的突破口。

### 2.2 第二站：记忆化搜索 —— 给回溯装上"缓存"（自顶向下）

既然 `(i, j)` 状态会被重复计算，那就用一张 `memo` 表把算过的结果缓存下来，下次直接查表。这就是**记忆化搜索**，它是回溯到 DP 最平滑的过渡。

```java
public class ZeroOne_dfs_memo implements ZeroOnePack {
    private int[][] memo;
    private int[] C, W;
    public int backPack(int[] C, int[] W, int V) {
        this.C = C; this.W = W;
        memo = new int[C.length + 1][V + 1];
        for (int[] row : memo) Arrays.fill(row, -1);   // -1 表示未计算
        return dfs(C.length - 1, V);
    }
    // dfs(i, j): 从前 i 件物品中选，容量为 j 时的最大价值
    private int dfs(int i, int j) {
        if (i < 0 || j <= 0) return 0;                 // 边界：无物品或无容量
        if (memo[i + 1][j] != -1) return memo[i + 1][j]; // 命中缓存
        if (j < C[i]) return memo[i + 1][j] = dfs(i - 1, j);  // 装不下，只能不选
        return memo[i + 1][j] = Math.max(
                dfs(i - 1, j),                         // 不选第 i 件
                dfs(i - 1, j - C[i]) + W[i]);          // 选第 i 件
    }
}
```

- **状态定义**：`dfs(i, j)` = 从前 `i` 件里选、容量 `j` 时的最大价值。
- **提速原理**：每个 `(i, j)` 只真正计算一次，之后 `O(1)` 查表。状态总数 `O(nV)`，故时间降为 `O(nV)`。
- **心智价值**：记忆化搜索**几乎不需要思考"遍历顺序"**——递归会自动帮你按依赖关系求解。它是 DP 初学者最友好的入口。

### 2.3 第三站：二维递推 —— 把递归翻译成循环（自底向上）

记忆化是"自顶向下"（从大问题递归到小问题）。把它反过来，从最小的子问题开始，用循环**自底向上**填一张二维表，就得到了经典的二维 DP。

```java
public class ZeroOne_dp_2d implements ZeroOnePack {
    public int backPack(int[] C, int[] W, int V) {
        int N = C.length;
        int[][] dp = new int[N + 1][V + 1];            // dp[i][v]: 前 i 件、容量 v 的最大价值
        for (int i = 1; i <= N; i++) {
            for (int v = 1; v <= V; v++) {
                dp[i][v] = dp[i - 1][v];               // 不选第 i 件（继承上一行）
                if (v >= C[i - 1]) {                   // 容量够，可以选
                    dp[i][v] = Math.max(dp[i][v],
                                        dp[i - 1][v - C[i - 1]] + W[i - 1]);
                }
            }
        }
        return dp[N][V];
    }
}
```

**状态转移方程**（本题的灵魂）：

```text
F[i][v] = max( F[i-1][v],                  ← 不选第 i 件，价值不变
               F[i-1][v-Cᵢ] + Wᵢ )         ← 选第 i 件，容量减 Cᵢ、价值加 Wᵢ
```

- **关键**：`dp[i][*]` 只依赖 `dp[i-1][*]`（**上一行**）。这个依赖关系是后续能压成一维的前提。
- **复杂度**：时间 `O(NV)`，空间 `O(NV)`。

### 2.4 第四站：一维滚动数组 —— 空间的极致压缩

既然第 `i` 行只依赖第 `i-1` 行，我们完全不需要保存整张二维表，**用一个一维数组反复覆盖（滚动）即可**。这就是 0-1 背包最经典的写法：

```java
public class ZeroOne_dp_1d implements ZeroOnePack {
    public int backPack(int[] C, int[] W, int V) {
        int[] dp = new int[V + 1];
        for (int i = 0; i < C.length; i++) {
            for (int v = V; v >= C[i]; v--) {          // ⚠️ 容量必须【倒序】遍历
                dp[v] = Math.max(dp[v], dp[v - C[i]] + W[i]);
            }
        }
        return dp[V];
    }
}
```

- **空间**：从 `O(NV)` 骤降到 `O(V)`。
- **⚠️ 最大的坑——容量必须倒序遍历**：这是 0-1 背包与完全背包唯一但致命的区别，下一章用数学原理讲透"为什么"。

### 2.5 四种写法对比总览

| 写法 | 方向 | 时间 | 空间 | 心智负担 | 定位 |
|---|---|---|---|---|---|
| 回溯 | — | `O(2ⁿ)` | `O(n)` | 最低 | 理解问题本质、暴力对拍基准 |
| 记忆化搜索 | 自顶向下 | `O(nV)` | `O(nV)` | 低（无需想遍历序） | DP 最友好入口 |
| 二维递推 | 自底向上 | `O(nV)` | `O(nV)` | 中 | 标准模板、易调试 |
| 一维滚动 | 自底向上 | `O(nV)` | **`O(V)`** | 高（倒序陷阱） | 面试/竞赛最终形态 |

> 💡 **学习建议**：初学先用**记忆化搜索**建立状态定义的直觉，再"翻译"成二维递推，最后压成一维。**能一维就一维是竞赛习惯，但工程调试时二维表更直观。**

## 三、数学建模与核心机制

这一章解决三个"知其所以然"的问题：转移方程怎么来的、一维为什么必须倒序、恰好装满型为什么初始化不同。这三点是 0-1 背包**最容易背错、也最能体现理解深度**的地方。

### 3.1 状态转移方程的推导

**第一步：定义状态。** 令 `F[i][v]` = 从前 `i` 件物品中挑选、且总费用不超过 `v` 时的**最大价值**。最终答案是 `F[N][V]`。

**第二步：考察最后一件物品（第 `i` 件）的决策。** 无非两种情况：

1. **不选第 `i` 件**：那么问题退化为"用前 `i-1` 件、容量仍为 `v`"，价值为 `F[i-1][v]`。
2. **选第 `i` 件**（前提 `v ≥ Cᵢ`）：先腾出 `Cᵢ` 的容量给它，剩下的 `v - Cᵢ` 容量留给前 `i-1` 件最优装填，再加上它自身价值 `Wᵢ`，即 `F[i-1][v-Cᵢ] + Wᵢ`。

**第三步：取两者最大。**

```text
              ⎧ F[i-1][v]                    , v <  Cᵢ （装不下，只能不选）
F[i][v] =     ⎨
              ⎩ max(F[i-1][v], F[i-1][v-Cᵢ]+Wᵢ) , v ≥ Cᵢ
```

**边界**：`F[0][v] = 0`（没有物品，价值为 0）。这个推导过程——"**盯住最后一个决策，把大问题拆成不含该决策的小问题**"——是所有背包乃至线性 DP 的通用套路。

### 3.2 一维滚动：为什么容量必须【倒序】遍历？（最经典的坑）

一维数组 `dp[v]` 复用同一行空间，本质是"用 `dp[v]` 的当前值代表 `F[i-1][v]`（旧值），更新后代表 `F[i][v]`（新值）"。转移方程 `dp[v] = max(dp[v], dp[v-Cᵢ]+Wᵢ)` 要求 `dp[v-Cᵢ]` 必须是**上一行（`i-1`）的旧值**。

**倒序遍历（`v` 从 `V` 递减到 `Cᵢ`）为什么对？**
> 更新 `dp[v]` 时用到的 `dp[v-Cᵢ]`，其下标 `v-Cᵢ < v`，而倒序意味着**较小的下标此刻还没被本轮更新过**，因此 `dp[v-Cᵢ]` 仍是上一行的旧值 ✅。这精确对应了 `F[i-1][v-Cᵢ]`。

**如果错误地正序遍历会怎样？**
> 正序时，`dp[v-Cᵢ]` 在本轮**已经被更新**成了 `F[i][v-Cᵢ]`（含第 `i` 件）。于是第 `i` 件物品可能被**重复选取多次**——这恰恰变成了**完全背包**（物品无限件）的语义！

用一个对照直击本质：

```text
0-1 背包（每件最多一次）：   for v = V .. Cᵢ   （倒序）
完全背包（每件可无限次）：   for v = Cᵢ .. V   （正序）
```

> 🎯 **记忆锚点**：**"倒序防重复，正序可重复"**——一个循环方向之差，就是 0-1 背包与完全背包的全部分野。

### 3.3 "最大价值型" vs "恰好装满型"：初始化的关键差异

参考题单里明确标注了 `<恰好装满型>`（如 LC 2915、3877）。这类问题与"最大价值型"在**初始化**上有一个极易踩坑的区别：

| 类型 | 问题诉求 | `dp` 初始化 | 原因 |
|---|---|---|---|
| **最大价值型**（本题） | 费用**不超过** `V` 的最大价值 | 全部初始化为 `0` | 任何容量下"什么都不装"都是合法的（价值 0） |
| **恰好装满型** | 费用**恰好等于** `V` | `dp[0]=0`，其余 `dp[1..V] = -∞` | 只有容量 0 能被"恰好装满"（空装）；其余容量在没有合法方案前是"不可达"状态 |

**为什么恰好装满要用 `-∞`？**
> `-∞` 代表"该容量状态尚不可达"。转移时 `dp[v-Cᵢ]` 若为 `-∞`，则 `dp[v-Cᵢ]+Wᵢ` 仍是极小值，`max` 不会误采纳这个非法状态。最终若 `dp[V]` 仍为 `-∞`，说明**无法恰好装满**。若初始化为 0，则会错误地把"未装满"当成"恰好装满价值为 0"。

> 类似地，**求方案数**的变体（如 LC 494 目标和），初始化为 `dp[0]=1`（空集是凑出 0 的一种方案），转移用**加法** `dp[v] += dp[v-Cᵢ]` 而非 `max`。

### 3.4 复杂度与"伪多项式"的本质

- **时间**：`O(NV)`。**空间**：二维 `O(NV)`，一维 `O(V)`。
- ⚠️ **一个深刻的理论细节——0-1 背包是"伪多项式（pseudo-polynomial）"算法**：复杂度 `O(NV)` 看似多项式，但 `V` 是一个**数值**，其编码长度是 `log V` 位。当 `V` 极大（如 `10^9`）时，`O(NV)` 会爆炸。正因如此，**0-1 背包（子集和）问题本质是 NP-完全的**，我们的 DP 只是在 `V` 不太大时才高效。这解释了为什么有些"背包题"当容量极大、但物品价值总和较小时，要**改用"价值维度"做 DP**（`dp[价值] = 最小费用`）。

## 四、变体家族与题型分类实战规律（核心重点）

这一章是全文落脚点。目标只有一个：**建立"看到题目就能识别出这是背包、且知道是哪种背包、该套哪个模板"的直觉。**

### 4.0 先建立"背包信号"雷达

出现以下信号，请立刻联想到背包 DP：

- 🎯 有一个**总容量 / 总预算 / 总限制**（背包容量 `V`）。
- 🎯 有一组**物品**，每个带"费用"和"价值"两个属性。
- 🎯 求"**不超过 / 恰好等于**某个限制下的最大价值 / 方案数 / 可行性"。
- 🎯 每个物品的选取次数受限（0-1：至多一次；完全：无限次；多重：至多 kᵢ 次）。
- 🎯 贪心（按性价比）能被反例证伪 → 大概率是背包 DP。

### 4.1 背包变体家族（同一套骨架，改循环即可）

所有背包变体共享"状态定义 + 转移取 max/sum"的骨架，差异集中在**循环方向**和**次数约束**上：

| 变体 | 每件物品可选次数 | 一维循环写法 | 记忆口诀 |
|---|---|---|---|
| **0-1 背包** | 至多 1 次 | 容量**倒序** `for v=V..Cᵢ` | 倒序防重复 |
| **完全背包** | 无限次 | 容量**正序** `for v=Cᵢ..V` | 正序可重复 |
| **多重背包** | 至多 `kᵢ` 次 | 二进制拆分 → 转 0-1；或单调队列优化 | 拆成 0-1 |
| **分组背包** | 每组至多选 1 件 | 组外层、容量倒序、组内物品最内层 | 组内互斥 |

> 本文聚焦 0-1 背包，但理解上表能让你在完全背包（如硬币凑数）、多重背包（有限件数）之间无缝切换。

### 4.2 0-1 背包的四大题型（基于参考题单）

真实算法题很少直接叫"背包"，而是把 `C/W/V` **伪装**起来。识别"谁是容量、谁是费用、谁是价值"是解题第一步。

#### 题型 I：标准最大价值型 —— 直接套模板

- **题眼**：明确的容量上限 + 物品的（费用，价值），求最大价值。
- **模型**：`C` = 费用，`W` = 价值，`V` = 容量，直接一维 DP。
- **代表题**：
  - **LintCode 125 / P1048 采药**：背包裸题，采药时间 = 容量，每株药（耗时，价值）。
  - 一般化的资源分配、预算选品问题。

#### 题型 II：可行性 / 等和分割型 —— 价值=费用的特例

- **题眼**：能否选出一个子集，其和**恰好等于**某个目标（常是总和的一半）。
- **建模技巧**：令**费用 = 价值 = 元素值**，容量 = 目标和；转化为"能否恰好装满容量 `target`"的**布尔背包**（`dp[v]` 为 boolean，转移用 `||`）。
- **代表题**：
  - **LC 416 分割等和子集**：判断能否选出和为 `sum/2` 的子集。`dp[v] = dp[v] || dp[v-num]`。
  - **LC 1049 最后一块石头的重量 II**：把石头分成两堆使差最小 = 尽量让一堆逼近 `sum/2`，转化为 0-1 背包求"不超过 `sum/2` 的最大和"，答案 `= sum - 2*maxHeap`。

#### 题型 III：方案数型 —— 转移从 max 变 sum

- **题眼**：求"有多少种选法"能凑出目标，而非最大价值。
- **建模技巧**：`dp[0] = 1`（空集是一种方案），转移 `dp[v] += dp[v-Cᵢ]`（**加法**替代 `max`）。
- **代表题**：
  - **LC 494 目标和**：给每个数添 `+/-` 使和为 `target`。设正数子集和为 `P`，则 `P = (sum + target)/2`，转化为"恰好装满容量 `P` 的方案数"，是 0-1 背包组合数的经典范式。⚠️ 注意 `(sum+target)` 需为非负偶数，否则无解。

#### 题型 IV：多维背包型 —— 容量升维

- **题眼**：有**两个（或多个）独立的容量约束**同时限制。
- **建模技巧**：`dp` 增加一维，`dp[j][k]`，两个容量维度都**倒序**遍历。
- **代表题**：
  - **LC 474 一和零**：字符串集合，约束是"最多 `m` 个 0 和 `n` 个 1"。费用变成二维 `(zeros, ones)`，价值是"选中字符串个数"。`dp[j][k] = max(dp[j][k], dp[j-zeros][k-ones] + 1)`。

#### 题型 V：恰好装满 / 最长子序列型

- **题眼**："恰好""正好达到"某目标下的最优（最长/最少/异或等）。
- **建模技巧**：初始化 `dp[0]=0`、其余为 `-∞`（不可达），见 3.3。
- **代表题**：LC 2915 和为目标值的最长子序列的长度、LC 3877 达到目标异或值的最少删除次数、LC 3946 购买最多物品数目 I。

### 4.3 从题目"翻译"到背包三要素（解题第一动作）

拿到疑似背包题，第一步永远是做这张"翻译表"：

| 题目里的东西 | 对应背包要素 |
|---|---|
| 总时间 / 总预算 / 总重量 / 目标和 | 容量 `V` |
| 每个物品消耗的时间 / 价格 / 重量 / 数值 | 费用 `Cᵢ` |
| 每个物品的收益 / 得分（有时 = 费用，有时恒为 1，有时是布尔） | 价值 `Wᵢ` |
| "至多不超过" | 初始化全 0，转移取 max |
| "恰好等于" | `dp[0]=0` 其余 `-∞` |
| "有多少种方案" | `dp[0]=1`，转移用 `+=` |
| "能否做到" | `dp` 为 boolean，转移用 `\|\|` |

**翻译对了，题就解了一大半。**

## 五、建模速查表与思维导图

### 5.1 0-1 背包题型分类与建模速查表 ⭐

> 全文最实用的一页。遇到题目先在此表定位题型，再确定初始化与转移。

| 题型分类 | 常见关键词（题眼） | 状态 / 转移核心 | 初始化 | 代表题 |
|---|---|---|---|---|
| **I. 标准最大价值** | 容量上限 + (费用,价值)，求最大价值 | `dp[v]=max(dp[v], dp[v-C]+W)` | 全 `0` | 采药 P1048、LintCode125 |
| **II. 可行性/等和分割** | 能否选子集和 = 目标 | 费用=价值=元素值；`dp[v]\|=dp[v-num]` | `dp[0]=true` | LC416、LC1049 |
| **III. 方案数** | 有多少种选法凑出目标 | `dp[v]+=dp[v-C]`（加法） | `dp[0]=1` | LC494 目标和 |
| **IV. 多维背包** | 两个独立容量约束 | `dp[j][k]=max(..,dp[j-a][k-b]+1)` | 全 `0` | LC474 一和零 |
| **V. 恰好装满/最长** | "恰好""正好达到"下的最优 | 同 I，但初始化不同 | `dp[0]=0`，余 `-∞` | LC2915、3877、3946 |

**通用一维模板（背下这一段即可应对绝大多数 0-1 背包）：**

```java
int[] dp = new int[V + 1];
// 恰好装满型：Arrays.fill(dp, Integer.MIN_VALUE); dp[0] = 0;
for (int i = 0; i < n; i++) {          // 枚举物品
    for (int v = V; v >= C[i]; v--) {  // ⚠️ 0-1 背包：容量倒序！
        dp[v] = Math.max(dp[v], dp[v - C[i]] + W[i]);
        // 方案数：dp[v] += dp[v - C[i]];
        // 可行性：dp[v] = dp[v] || dp[v - C[i]];
    }
}
return dp[V];
```

### 5.3 一图流决策：拿到题该怎么建模？

```text
物品能否切分 / 局部最优能拼全局吗？
  ├─ 能 → 贪心（不是背包）
  └─ 不能（0-1 离散取舍）↓

  求什么？
  ├─ 最大/最小价值 ────────→ 转移取 max/min，初始化全 0
  ├─ 能否恰好达到目标 ─────→ 布尔 dp，初始化 dp[0]=true
  ├─ 有多少种方案 ─────────→ 转移用 +=，初始化 dp[0]=1
  └─ 恰好装满下的最优 ─────→ 初始化 dp[0]=0 其余 -∞

  每件物品选几次？
  ├─ 至多 1 次 → 0-1 背包（容量倒序）
  ├─ 无限次   → 完全背包（容量正序）
  └─ 至多 kᵢ 次 → 多重背包（二进制拆分转 0-1）

  有几个独立约束维度？
  └─ ≥2 个 → 多维背包（dp 升维，各维都倒序）
```

## 六、尾声：一句话记忆锚点

把全文浓缩成三句话，帮你在考场和工程现场瞬间召回：

> 🎯 **演进主线**：0-1 背包四种写法是一条思维链——**回溯发现重复子问题 → 记忆化缓存它 → 递推翻译成循环 → 滚动压掉一维**。这条链就是学会任何 DP 的通用路径。

> 🎯 **核心口诀**：**"倒序防重复，正序可重复"**——一维背包的循环方向，就是 0-1 与完全背包的全部分野；**"不超过全填 0，恰好装满填负无穷，数方案填 1"**——初始化决定了你在解哪一类问题。

> 🎯 **建模直觉**：拿到题先做翻译——**谁是容量、谁是费用、谁是价值**；翻译对了，题就解了一大半。**能贪就贪，不可切分的离散取舍，就交给背包。**
