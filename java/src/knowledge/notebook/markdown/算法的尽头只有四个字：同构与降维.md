# 算法的尽头只有四个字：同构与降维

**——从括号生成到卡特兰数，聊聊算法背后真正在干什么**

---

刷题到一定量级，你会发现一件奇怪的事：很多表面完全不同的题，写完之后代码几乎一样。括号生成和二叉搜索树计数，一个拼字符串一个建树，但 DP 方程一字不差。合法的进出栈序列数量？还是同一个方程。

这不是巧合，是必然。

如果非要用一句话概括高级算法在干什么，我的答案是：**找到不同问题之间的同构关系，然后一层一层降维，直到降到数学公式为止。**

这篇文章从一道括号生成出发，把这个过程完整走一遍。

---

## 一、降维的起点：从 造出来 到 数出来

### 1.1 先看一个简单的例子热热身

爬楼梯。每次走 1 阶或 2 阶，问 n 阶有多少种走法。

最暴力的做法是递归：`f(n) = f(n-1) + f(n-2)`，不加缓存就是 O(2ⁿ) 的指数爆炸。加个数组记一下算过的值，变成 O(n)。再观察一下这个递推式——这不就是斐波那契数列吗？有通项公式，理论上 O(1) 就能算。

从 O(2ⁿ) 到 O(n) 到 O(1)，每一步做的事情都是同一件：**发现问题内部的结构，利用结构压缩计算量。** 这就是降维。

**暴力递归（O(2ⁿ)）：**

```java
// 不加缓存的递归，指数级爆炸
public int climbStairs(int n) {
    if (n <= 1) return 1;
    return climbStairs(n - 1) + climbStairs(n - 2);
}
```

**加缓存（O(n)）：**

```java
// 加个数组记一下，每个子问题只算一次
public int climbStairs(int n) {
    int[] dp = new int[n + 1];
    dp[0] = 1; dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}
```

**再压到 O(1) 空间：**

```java
// 只需要前两个值，滚动变量就够了
public int climbStairs(int n) {
    int a = 1, b = 1;
    for (int i = 2; i <= n; i++) {
        int tmp = a + b;
        a = b;
        b = tmp;
    }
    return b;
}
```

从暴力递归到 DP 到滚动变量，同一个问题，三种写法，复杂度逐级下降。结构没变，变的是你对结构的利用程度。

括号问题的降维链条更长、更精彩。

### 1.2 第一站：生成所有合法括号（回溯）

题目：给 n 对括号，生成所有合法的组合。

思路很自然——在每个位置做选择，左括号不超过 n，右括号不超过当前左括号数，递归到底就收集结果。这是标准的 DFS + 回溯。

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> res = new ArrayList<>();
        char[] path = new char[n * 2];
        dfs(path, 0, 0, 0, n, res);
        return res;
    }

    private void dfs(char[] path, int index, int l, int r, int n, List<String> res) {
        if (index == path.length) {
            res.add(new String(path));
            return;
        }
        if (l < n) {
            path[index] = '(';
            dfs(path, index + 1, l + 1, r, n, res);
        }
        if (r < l) {
            path[index] = ')';
            dfs(path, index + 1, l, r + 1, n, res);
        }
    }
}
```

这里已经用了 `char[]` 替代 `StringBuilder` 的优化版本。

一个值得注意的优化：题目的输出长度严格是 2n，这是个定值。所以用 `char[]` 替代 `StringBuilder`，指针往前走就是写入，递归回来指针自然缩小，下次写入直接覆盖旧数据。连 `deleteCharAt` 的撤销动作都不需要了。

> **回溯的本质是状态的保存与恢复。最快的恢复方式不是 撤销 ，是 覆盖 。**

但不管怎么优化实现细节，时间复杂度是 O(4ⁿ/√n)。因为题目要的是所有具体字符串，你得把每一个都实打实造出来，没有捷径。

**关键转折：如果题目只问 有多少种 呢？**

### 1.3 第二站：只数数量（DP 建模）

需求变成返回一个 `int`。这时候继续用回溯把所有字符串生成出来再 count，就是杀鸡用牛刀——你花了指数级的时间去构建了一堆你根本不需要的东西。

**降维的第一步，永远是问自己：我真正需要的信息是什么？能不能绕过那些不需要的中间产物？**

这里需要的只是 数量 。那就找一种方式，只算数量，不造实体。

核心建模的思路，其实跟拆快递差不多。

想象你收到一个很长的包裹（一个括号序列），你想弄清楚它的内部结构。最自然的做法是什么？**找到第一个可以拆开的地方，打开它。**

对于括号序列来说，这个「第一个拆开的地方」就是：**第一个左括号 `(` 和跟它配对的那个右括号 `)`**。

拿 `(())()` 举例。第一个 `(` 在位置 0，跟它配对的 `)` 在位置 3。这一对括号就像包裹的外壳，拆掉之后里面露出两段东西：
- **A** = `()`，夹在外壳里面的部分
- **B** = `()`，外壳右边剩下的部分

所以原序列 = **( A ) B** = `(` `()` `)` `()` = `(())()`。

为什么这种拆法**绝对不会重复**？

关键在于我们锁定的是「第一个左括号的配对位置」。任何一个合法序列，它的第一个 `(` 跟谁配对是一个**确定的、唯一的事实**——不是我们选的，是序列本身决定的。配对位置不同，拆出来的 A 和 B 长度组合就不同。就像按身份证号分人群，每个人只会被分到一个组里，绝不会被数两次。

为什么**绝对不会遗漏**？

因为每个合法序列都至少有一个 `(`（空串用 dp[0]=1 兜底），所以每个序列都能被这种方式拆开，没有「拆不动」的情况。

有了这个拆分，状态转移就是做加法和乘法：总共 i 对括号，外壳消耗 1 对，剩 i-1 对分给 A 和 B。A 占 j 对、B 占 i-1-j 对时，方案数是 `dp[j] * dp[i-1-j]`（乘法原理：A 的每种填法搭配 B 的每种填法）。让 j 从 0 遍历到 i-1 累加，就是 `dp[i]`。

```java
class Solution {
    public int countParenthesis(int n) {
        int[] dp = new int[n + 1];
        dp[0] = 1;
        for (int i = 1; i <= n; i++)
            for (int j = 0; j < i; j++)
                dp[i] += dp[j] * dp[i - 1 - j];
        return dp[n];
    }
}
```

等价的写法是 DFS + 记忆化搜索，状态定义为「剩余左/右括号数」：

```java
class Solution {
    public int countParenthesis(int n) {
        int[][] memo = new int[n + 1][n + 1];
        for (int[] row : memo) Arrays.fill(row, -1);
        return dfs(n, n, memo);
    }

    private int dfs(int left, int right, int[][] memo) {
        if (left == 0 && right == 0) return 1;
        if (left < 0 || left > right) return 0;
        if (memo[left][right] != -1) return memo[left][right];
        return memo[left][right] = dfs(left - 1, right, memo) + dfs(left, right - 1, memo);
    }
}
```

两种写法时间都是 O(n²)，本质相同，方向不同——一个自底向上填表，一个自顶向下按需计算。

回头看这个 (A)B 拆法，它有一个漂亮的性质：**不同的 j 值产生的序列集合完全不重叠。** j=0 时外壳紧挨着（配对在位置 1），j=1 时外壳里夹一对，j=2 时夹两对……每种情况泾渭分明。这在数学上叫「正交分解」——子问题没有交集，加起来就是全集。

> **如果你发现自己在用 HashSet 去重，通常意味着子问题划分出了重叠。好的 DP 建模，天然不重复——因为它从建模那一刻起，就把方案空间切得干干净净。**

时间复杂度从指数级降到了 O(n²)。这是第一次降维。

## 二、降维的方法论：三个问题和两个案例

括号问题展示了一种降维：从"生成所有实体"降到"只算数量"。但降维这件事远不止于此。它是一套可以反复应用的建模思路。

每次降维，本质上都是回答同一个问题：

> **"我当前的计算中，哪些工作是重复的？哪些信息是多余的？"**

找到答案之后，就是三个动作：

1. **去掉重复计算**：同一个子问题被算了很多次，记下来。（记忆化 / DP）
2. **去掉多余状态**：状态表示里有些维度其实不需要，压掉。（状态压缩）
3. **去掉多余遍历**：某些组合根本不可能产生答案，跳过。（剪枝 / 贪心）

下面用两个经典问题，把这套方法论走一遍。

### 2.1 案例一：子数组最大和（三次降维）

题目：给一个整数数组，找连续子数组的最大和。

**第一版：暴力枚举，O(n³)**

最直接的思路：枚举所有起点 i、终点 j，然后内层循环求 sum(i..j)。三层循环，O(n³)。

```java
// O(n³)：枚举所有子数组，逐个求和
public int maxSubArray(int[] nums) {
    int max = Integer.MIN_VALUE;
    for (int i = 0; i < nums.length; i++)
        for (int j = i; j < nums.length; j++) {
            int sum = 0;
            for (int k = i; k <= j; k++) sum += nums[k];
            max = Math.max(max, sum);
        }
    return max;
}
```

**第一次降维：去掉重复计算，O(n²)**

观察：sum(i..j) 和 sum(i..j-1) 只差一个元素。第三层循环完全是重复劳动。去掉它，把 sum 累加到第二层循环里。

```java
// O(n²)：累加代替重新求和
public int maxSubArray(int[] nums) {
    int max = Integer.MIN_VALUE;
    for (int i = 0; i < nums.length; i++) {
        int sum = 0;
        for (int j = i; j < nums.length; j++) {
            sum += nums[j]; // 在上一次的基础上加一个元素
            max = Math.max(max, sum);
        }
    }
    return max;
}
```

**第二次降维：去掉多余状态，O(n)**

关键洞察：如果前面的累加和已经变成负数了，那它对后续元素只有拖累，不如丢掉重新开始。所以我们不需要记住"从哪里开始"，只需要维护"以当前位置结尾的最大和"这一个变量。

这就是 Kadane 算法：

```java
// O(n)：前缀和变负就丢掉，只保留"有用的历史"
public int maxSubArray(int[] nums) {
    int max = nums[0], cur = nums[0];
    for (int i = 1; i < nums.length; i++) {
        cur = Math.max(nums[i], cur + nums[i]); // 要么接上前面，要么从这里重新开始
        max = Math.max(max, cur);
    }
    return max;
}
```

三次降维的逻辑：
- O(n³) → O(n²)：发现重复计算（sum 每次重新累加），用累加替代。
- O(n²) → O(n)：发现多余状态（负数前缀和对未来无用），果断丢弃。

每次降维背后的思维转变：第一次是"不要重复算"，第二次是"不要记无用的东西"。

> **降维的核心动作就是"丢"——丢掉重复的计算，丢掉多余的状态，丢掉没用的历史。你每丢掉一样东西，复杂度就降一级。**

### 2.2 案例二：0-1 背包的状态压缩（从二维到一维）

题目：n 个物品各有重量和价值，背包容量为 W，每个物品只能选或不选，求最大价值。

标准 DP 的状态定义是二维的：`dp[i][w]` 表示前 i 个物品、容量为 w 时的最大价值。状态转移：

```plaintext
dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])
```

这里有一个关键观察：**第 i 行只依赖第 i-1 行。** 更早的行（i-2, i-3...）已经没用了。

这意味着"物品编号"这个维度是可以压掉的——我们只需要一个一维数组，滚动更新就行：

```java
// 二维 DP：O(nW) 时间，O(nW) 空间
public int knapsack2D(int[] weight, int[] value, int n, int W) {
    int[][] dp = new int[n + 1][W + 1];
    for (int i = 1; i <= n; i++)
        for (int w = 0; w <= W; w++) {
            dp[i][w] = dp[i - 1][w]; // 不选第 i 个
            if (w >= weight[i - 1])
                dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - weight[i - 1]] + value[i - 1]);
        }
    return dp[n][W];
}
```

```java
// 一维 DP：O(nW) 时间，O(W) 空间——空间降了一个维度
public int knapsack1D(int[] weight, int[] value, int n, int W) {
    int[] dp = new int[W + 1];
    for (int i = 0; i < n; i++)
        for (int w = W; w >= weight[i]; w--) // 倒序遍历，保证每个物品只用一次
            dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);
    return dp[W];
}
```

为什么倒序遍历？这块值得多说两句，因为它是无数算法新手的噔梦。

用一个现实场景来类比。假设你是一个寻宝猎人，面前有一排宝箱（下标从 0 到 W），每个宝箱里记着一个数字：「上一轮挑完东西后，这个容量能装的最大价值」。现在轮到新物品上场，你要决定要不要把它塞进去。

**如果从左往右更新（正序），会发生什么？**

假设新物品重 3、价值 5。你站在 `dp[3]` 前，发现 `dp[3-3] + 5 = dp[0] + 5`，比原来大，于是更新了 `dp[3]`——相当于把新物品塞进了容量为 3 的宝箱。没问题。

然后你往右走到 `dp[6]`，发现 `dp[6-3] + 5 = dp[3] + 5`。但注意！这个 `dp[3]` 已经不是「上一轮」的值了，它是你**刚刚在这一轮**塞了新物品之后的值。等于什么？等于你在容量 3 那里已经拿了一次新物品，现在在容量 6 这里又拿了一次——**同一个物品被你拿了两次。** 这就变成了「完全背包」而不是 0-1 背包了。

**从右往左更新（倒序），问题就消失了。**

你先站在最右边的大宝箱 `dp[W]` 前，查询 `dp[W-3]`——这时候左边的箱子还没被动过，里面存的还是上一轮的老值。然后往左走，每一步查询的都是「还没被当前轮撢过的箱子」。这样，每个物品在每轮里最多只被拿一次，严格符合 0-1 背包的规则。

一句话总结：**倒序是为了读到「上一轮」的值而不是「当前轮」的值。它用遍历顺序取代了额外的数组拷贝，用时序上的小技巧省下了空间上的大开销。**

这次降维的逻辑：
- 观察依赖关系：当前状态只依赖前一层
- 得出结论：历史层是多余的，可以丢掉
- 压缩状态：用一维数组 + 遍历顺序控制，代替二维表

> **状态压缩的本质是"认清依赖边界"。当你知道未来只需要最近一层的历史时，就没必要扣着所有历史不放。**

### 2.3 降维方法论小结

把上面两个例子和前面的括号问题放在一起看，降维有一套固定的建模节奏：

1. **写出暴力解**，让它跑起来。不要急着优化，先让逻辑正确。
2. **盯着暴力解问：哪里在做无用功？** 是重复算了同一个子问题？是保存了永远不会再访问的历史状态？还是遍历了明显不可能的分支？
3. **根据答案选择工具**：重复计算 → 加缓存；多余状态 → 压缩维度；无用遍历 → 剪枝或贪心。

所有的降维，本质上都是在回答同一个问题：**"这个计算里，什么是可以不要的？"** 丢掉重复，丢掉冗余，丢掉无用。丢得越干净，复杂度越低。

## 三、同构：发现不同问题是同一个问题

降维解决的是"怎么更快地算"。但算法更深层的事情是——**发现原来你在算的东西，跟另一个看起来完全不同的东西，其实是同一个东西。**

同构的感觉，往往最先出现在同一道题的不同解法之间。

### 3.1 同一道题的两张脸：括号生成 vs 括号计数

括号生成（LeetCode 22）要你返回所有具体的括号组合，括号计数要你返回组合的个数。表面看这是两道题，但它们共享同一个核心结构。

回溯法怎么做？每个位置选左括号或右括号，约束是 left < n 和 right < left。它遍历的是一棵"受限的决策树"——每个叶子节点就是一个合法序列。

DP 怎么做？拿 (A)B 结构拆解，`dp[i] = ∑ dp[j] × dp[i-1-j]`。它不关心每个序列长什么样，只关心数量。

两种解法的状态空间完全不同——一个是"已用的左/右括号数"，一个是"括号对数"。但它们计算的东西完全一致：都是在数"满足前缀约束的序列"有多少种。

而且它们产出的数列相同：1, 1, 2, 5, 14, 42……

这就是同一道题内部的"同构"：**两种完全不同的建模角度，最终收敛到同一个数学对象。** 当你在一道题里发现了这种现象，自然会问：还有没有其他题目，也收敛到这个数列？

答案是有，而且还不少。

### 3.2 二叉搜索树计数

LeetCode 96：给 n 个节点，能组成多少种不同的二叉搜索树？

拆法：选一个节点做根，比它小的放左边，比它大的放右边。如果左子树有 k 个节点，右子树就有 n-1-k 个。方案数是 `dp[k] × dp[n-1-k]`，遍历所有 k 累加。

写出来之后你会愣住——**这个方程和括号的 (A)B 完全一样。**
- 括号：外壳 `()` = 1 对，内部 A = j 对，外部 B = i-1-j 对
- 二叉树：根 = 1 个节点，左子树 = k 个，右子树 = n-1-k 个

初始条件都是 dp[0] = 1，递推方程相同，数列相同：1, 1, 2, 5, 14, 42……

把 BST 的 DP 写出来，和括号的对比一下：

```java
// 不同的二叉搜索树（LeetCode 96）
class Solution {
    public int numTrees(int n) {
        int[] dp = new int[n + 1];
        dp[0] = 1;
        for (int i = 1; i <= n; i++)
            for (int j = 0; j < i; j++)
                dp[i] += dp[j] * dp[i - 1 - j]; // 与括号 DP 完全相同
        return dp[n];
    }
}
```

代码一模一样，这不是巧合，是同构。

### 3.3 合法的进出栈序列

再看一个问题：n 个元素依次进栈，问有多少种不同的合法出栈顺序？

把"进栈"看成 `(`，"出栈"看成 `)`。合法的约束是：任何时刻出栈次数不能超过进栈次数——**这和括号的约束一模一样。**

所以 n 个元素的合法出栈序列数，也是第 n 个卡特兰数。

### 3.4 建立双射：四个问题是同一个问题

这四个问题——括号生成/计数、BST 形态、进出栈序列——不只是"答案相同"。它们之间存在精确的一一对应。

括号 → 二叉树的翻译规则：
- 一对匹配的 `()` → 一个节点
- 内部的 A → 左子树
- 右边的 B → 右子树
- 空串 → null

括号 → 进出栈序列的翻译规则：
- `(` → push
- `)` → pop

拿 n=3 试一下。`(())()` 拆成 (A)B，A=`()`，B=`()`。翻译成树：根节点的左子树是一个节点，右子树也是一个节点——就是那棵以 2 为根的平衡二叉树。翻译成栈操作：push push pop push pop pop——进1进2出2进3出3出1。

5 个括号序列、5 棵不同的 BST、5 种不同的出栈顺序，三者之间存在精确的一一对应。

> **这就是 同构 。三个不同领域的问题，剥掉物理外衣之后，骨架是同一个。**

一旦你认出了同构关系，在一个问题上积累的所有理解——建模方式、优化手段、边界处理——可以零成本搬到另一个问题上。

### 3.5 统一的名字：卡特兰数

这个反复出现的数列 1, 1, 2, 5, 14, 42…… 有一个统一的名字：**卡特兰数（Catalan Number）**。

它描述的是所有 分支且不交叉 结构的计数。括号的嵌套不交叉，树的子树不交叉，栈的进出不交叉，凸多边形的三角剖分对角线不交叉——全是同一个数学对象的不同物理实现。

## 四、降维的终点：从算法到数学公式

认出同构之后，下一步是问：**这个 O(n²) 的 DP，有没有闭式解？**

有。卡特兰数的通项公式是：

$$C_n = \frac{1}{n+1}\binom{2n}{n}$$

这个公式怎么来的？有一个非常漂亮的几何证明——安德烈反射原理。纯文字描述可能有点抽象，但只要跟着我的步骤在脑子里画一遍，就能明白。

**第一步：在脑子里画一个坐标系。**

横轴是步数（从 0 到 2n），纵轴是"当前未配对的左括号数"。每遇到一个 `(`，往右上走一步（y+1）；每遇到一个 `)`，往右下走一步（y-1）。n 对括号就是一条从原点 (0,0) 出发，向右拘拘地走 2n 步，最终回到纵坐标 0（即 (2n, 0)）的折线。

合法序列是什么意思？就是这条折线**全程不跌到 x 轴下方**——y 始终 ≥ 0。想象 x 轴是地平线，你的折线必须始终走在地面上或地面以上。

**第二步：数所有路径。**

不管合不合法，从 (0,0) 走到 (2n,0) 的所有折线总共有多少条？2n 步里选 n 步向上，其余自动向下。答案是组合数 C(2n, n)。

**第三步：数非法路径——这是关键。**

非法路径就是那些在某个时刻跌到了地平线以下的路径，也就是触碰到了 y = -1 这条「警戒线」。直接数它们很难，但安德烈发明了一个巧妙的「折纸」技巧。

想象任何一条非法路径。它从 (0,0) 出发，在某一步第一次触碰到 y = -1。就停在这个点，这是「第一次踩线」的位置。

现在做一个动作：**把这个触碰点之后的整段路径，沿着 y = -1 这条线对折翻转。** 就像拿一张纸，沿着警戒线对折——原来向上走的步变成向下走，原来向下走的变成向上走。

翻转前，剩余路径走向终点 (2n, 0)。翻转后呢？因为是关于 y = -1 做镜像，终点的 y 坐标从 0 变成了 -2（离警戒线距离 1，翻到另一侧也是距离 1，所以是 -1-1 = -2）。也就是说，翻转后的路径终点变成了 **(2n, -2)**。

这个翻转动作有一个精妙的性质：它是一一对应的。每一条非法路径（从 (0,0) 到 (2n,0)，中途触碰 y=-1）翻转后，都对应唯一一条从 (0,0) 到 (2n,-2) 的路径；反过来也一样。所以：

**非法路径数 = 从 (0,0) 到 (2n,-2) 的所有路径数 = C(2n, n-1)**

（为什么是 C(2n, n-1)？走到 (2n,-2) 意味着向上 n-1 步、向下 n+1 步，所以从 2n 步里选 n-1 步向上。）

**第四步：做减法。**

合法路径数 = 总路径数 - 非法路径数 = C(2n,n) - C(2n,n-1)。

化简一下，就得到通项公式。整个证明的精华就在「折纸」那一下：一个几何变换，把难以直接计数的「非法路径」变成了很容易计数的「另一个终点的所有路径」。这本身就是一次降维——把"带约束的计数"变成"无约束的计数"。

有了通项公式，还能推出相邻项递推：

$$C_n = C_{n-1} \times \frac{4n-2}{n+1}$$

一个循环，O(n) 时间，O(1) 空间。

```java
// 卡特兰数递推：O(n) 时间，O(1) 空间
class Solution {
    public int countParenthesis(int n) {
        long ans = 1;
        for (int i = 1; i <= n; i++)
            ans = ans * (4 * i - 2) / (i + 1);
        return (int) ans;
    }
}
```

**从回溯的 O(4ⁿ) → DP 的 O(n²) → 公式的 O(n)。三次降维，每次都是因为发现了更深层的结构。**

## 五、回过头来看这条路

把整个过程串起来，其实就是三步：

**第一步：建模。** 面对具体问题，找到它的核心约束和递归结构。括号的 (A)B 拆分、二叉树的"根+左+右"拆分，本质上是同一种建模方式——找到一个"锚点"把大问题正交地切成子问题。

**第二步：持续降维。** 有递推方程就找闭式解，有闭式解就找更快的计算方式。每一步降维的背后，都是对问题结构的更深理解。

**第三步：识别同构。** 写完一个问题的 DP 之后，去跟你见过的其他问题对比。如果状态转移方程完全相同，那它们就是同构的。同构意味着你可以复用所有已知的结论——包括数学上的闭式解。

这三步不只适用于算法题。

DP 的"记住算过的东西"，在工程里是缓存，在工作中是复盘沉淀。同构的"认出不同问题是同一个问题"，在架构设计里是抽象复用，在跨领域学习中是迁移类比。正交分解的"保证子问题不重叠"，在系统设计里是服务边界划分，在决策中是选项之间不内耗。

说到底，算法练的不是背模板的能力。它练的是**看到一个复杂的东西，能不能把它拆干净、认出它的本质、压到最简。**

这个能力用在哪里都管用。
