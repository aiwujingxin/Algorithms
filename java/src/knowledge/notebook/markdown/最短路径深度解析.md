# 最短路径（Shortest Path）深度解析：从 BFS 到 Dijkstra，再到分层图与全源最短路

> **一句话总纲**：最短路径问题的本质，是在图这个"状态空间"里寻找一条总代价最小的演化路径。它看似算法众多：BFS、0-1 BFS、Dijkstra、Bellman-Ford、SPFA、Floyd、Johnson、A*、拓扑序 DP……但核心决策其实只有三问：**边权是什么类型？要查单源还是多源？状态是否需要扩展？** 回答清楚这三问，算法选择就不再靠背，而是自然落地。

本文沿着"**问题从哪里来 → 如何建模成图 → 如何按边权和查询类型选算法 → 每个算法的正确性直觉 → 典型题型怎么识别**"这条主线，把最短路径专题系统讲透。

## 一、最短路径的起源与建模哲学

### 1.1 它到底为了解决什么问题？

最短路径问题的原型非常朴素：给定一张图 `G=(V,E)`，每条边有一个代价 `w(u,v)`，问从源点 `s` 到目标点 `t`，或者从源点 `s` 到所有点的**最小总代价**。

现实世界中，它对应大量问题：

- 地图导航：从上海到北京的最短时间 / 最少费用路线。
- 网络路由：数据包从一台机器到另一台机器的最低延迟路径。
- 游戏寻路：角色绕开障碍到达终点。
- 任务规划：在状态空间中从初始状态转移到目标状态的最小代价。
- 算法题：网格最小体力、K 站中转、钥匙开锁、阈值距离城市、概率最大路径。

最短路之所以重要，是因为它不仅是一个"图论问题"，更是一个**状态空间搜索框架**：

> **节点不一定是真实地点，也可以是"状态"；边不一定是真实道路，也可以是一次操作；边权不一定是距离，也可以是时间、金钱、体力、概率损失、障碍代价。**

### 1.2 图建模的三件事：点、边、权

任何最短路题，第一步都不是写算法，而是完成三件翻译：

| 建模元素 | 要问自己的问题 | 例子 |
|---|---|---|
| **点（Vertex）** | 一个状态应该如何表示？ | 城市编号、网格坐标、`(位置, 剩余次数)`、`(位置, 钥匙集合)` |
| **边（Edge）** | 什么操作会让状态转移？ | 走到相邻格、乘坐航班、使用一次折扣、拿起钥匙 |
| **权（Weight）** | 这次转移的代价是什么？ | 距离、费用、时间、障碍数、体力差、概率乘积 |

最短路径建模的关键，不在于套哪个算法，而在于**把题目里的限制条件变成状态的一部分**。例如：

- K 站中转限制 → 状态扩展为 `(城市, 已用中转数)` 或 `(城市, 剩余中转数)`。
- 可以使用一次半价券 → 状态扩展为 `(城市, 是否已使用优惠)`。
- 钥匙开锁问题 → 状态扩展为 `(位置, keysMask)`。
- 网格路径体力最小化 → 边权不是累计距离，而是路径上最大高度差的瓶颈值。

### 1.3 最短路的三类查询

| 查询类型 | 问什么 | 常用算法 |
|---|---|---|
| **单源最短路（SSSP）** | 从一个源点 `s` 到所有点 | BFS / 0-1 BFS / Dijkstra / Bellman-Ford / SPFA / DAG DP |
| **单点对最短路** | 从 `s` 到 `t` | 单源算法提前终止；A* 可加启发式 |
| **全源最短路（APSP）** | 任意两点间最短路 | Floyd-Warshall / Johnson / 对每个点跑 Dijkstra |

一个常见误区是：看到"很多点之间都要查"就直接 Floyd。事实上：

- `n` 小、图稠密 → Floyd 简洁稳定。
- `n` 大、图稀疏、边权非负 → 多次 Dijkstra 更合适。
- 图稀疏且有负边无负环 → Johnson。

### 1.4 最短路里的"最优子结构"

最短路径成立的核心性质是：

> 如果 `s → ... → t` 是一条最短路径，那么其中任意一段子路径 `u → ... → v` 也必须是 `u` 到 `v` 的最短路径。

否则，如果存在一条更短的 `u → v` 子路径，就能替换原路径中的那一段，使整体更短，矛盾。

这就是最短路算法能通过"松弛（relaxation）"逐步逼近答案的根本原因。

## 二、算法全景与选择决策树

### 2.1 先看边权，再看查询范围

最短路径算法选择的第一原则：**边权决定算法。**

| 边权类型 / 图结构 | 推荐算法 | 时间复杂度 | 适用场景 |
|---|---|---:|---|
| 无权图 / 所有边权相同 | BFS | `O(V+E)` | 普通层序最短步数 |
| 边权只在 `{0,1}` | 0-1 BFS | `O(V+E)` | 免费/付费两类代价、障碍 0/1 |
| 非负边权 | Dijkstra + 优先队列 | `O((V+E) log V)` | 最经典单源最短路，适合稀疏图 |
| 有负权、无负环 | Bellman-Ford | `O(VE)` | 可检测负环，稳定但慢 |
| 有负权、通常较稀疏 | SPFA | 平均较快，最坏 `O(VE)` | 工程/竞赛中谨慎使用 |
| 任意权重、全源查询、点数小 | Floyd-Warshall | `O(V^3)` | 多源最短路、传递闭包、阈值距离 |
| 稀疏图全源、有负边无负环 | Johnson | `O(VE + V(E+V)logV)` | 稀疏 APSP |
| DAG | 拓扑序 DP | `O(V+E)` | 有向无环图最短路 |
| 单点对 + 可设计启发函数 | A* | 依赖启发式 | 地图 / 网格寻路 |
| 状态带层数 / 道具 / 约束 | 分层图最短路 | 通常 `O(状态数 log 状态数)` | 扩点：位置 + 状态 |

> 注：参考索引中 Johnson 复杂度写作 `O(V^E * V^2 logV)` 应为笔误。经典 Johnson 是先 Bellman-Ford 重标权 `O(VE)`，再对每个源点跑 Dijkstra，总复杂度约为 `O(VE + V(E+V)logV)`。

### 2.2 一图流算法选择决策树

```text
边权是否全相等 / 无权？
  └─ 是 → BFS，O(V+E)

边权是否只为 0 或 1？
  └─ 是 → 0-1 BFS，O(V+E)

图是否是 DAG？
  └─ 是 → 拓扑序 DP，O(V+E)，可支持负权

是否存在负权边？
  ├─ 否 → Dijkstra + 优先队列
  └─ 是 → 是否有负环？
        ├─ 有 → 最短路无定义（可无限变小）
        └─ 无 → Bellman-Ford / SPFA

是否要所有点对最短路？
  ├─ 点数小 / 图稠密 → Floyd-Warshall
  ├─ 稀疏且非负边 → 对每个点跑 Dijkstra
  └─ 稀疏且有负边无负环 → Johnson

题目是否有 K 次、钥匙集合、优惠券、时间灯等额外限制？
  └─ 是 → 分层图 / 状态压缩图，把状态扩进节点
```

### 2.3 所有最短路算法的共同语言：松弛

无论 Dijkstra、Bellman-Ford、SPFA 还是 Floyd，本质都在做一件事：**松弛（relax）**。

对边 `(u, v, w)`：

```text
if dist[v] > dist[u] + w:
    dist[v] = dist[u] + w
```

这句话的含义是：如果"先到 `u` 再走边 `u→v`"比当前已知的 `v` 更短，就更新 `v`。

不同算法的区别，只在于：

- **按什么顺序松弛边？**
- **何时可以确信某个点的 dist 已经最终确定？**
- **是否允许负权导致已经确定的点被重新改小？**

Dijkstra 的答案是：非负边权下，每次取当前最小 `dist` 的点，它就已确定。Bellman-Ford 的答案是：不相信任何局部确定性，暴力松弛所有边 `V-1` 轮。Floyd 的答案是：枚举中转点 `k`，逐步允许更多中转。

## 三、核心算法深度解析

### 3.1 BFS：无权图的最短路

#### 适用条件

- 图无权，或所有边权相同。
- 目标是最少边数 / 最少步数。

#### 核心思想

BFS 按层扩展：从源点出发，第一层是距离 1 的点，第二层是距离 2 的点……因此**第一次到达某个点时，就是最短步数**。

```java
Queue<Integer> q = new ArrayDeque<>();
Arrays.fill(dist, INF);
dist[s] = 0;
q.offer(s);
while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : graph[u]) {
        if (dist[v] == INF) {
            dist[v] = dist[u] + 1;
            q.offer(v);
        }
    }
}
```

#### 正确性直觉

队列保证按距离非递减顺序出队。若一个点第一次被访问时距离为 `d`，任何之后到达它的路径都至少来自第 `d` 或更深层，不可能更短。

### 3.2 0-1 BFS：边权只有 0 和 1 时的线性 Dijkstra

#### 适用条件

- 边权仅为 `0` 或 `1`。
- 或问题可通过拆边 / 转换变成 `{0,1}` 权重。

#### 核心思想

用**双端队列**代替优先队列：

- 走一条权重 `0` 的边，距离不变，应当尽快处理 → 放队首。
- 走一条权重 `1` 的边，距离 +1，优先级稍低 → 放队尾。

```java
Deque<Integer> dq = new ArrayDeque<>();
Arrays.fill(dist, INF);
dist[s] = 0;
dq.offerFirst(s);
while (!dq.isEmpty()) {
    int u = dq.pollFirst();
    for (Edge e : graph[u]) {
        int v = e.to, w = e.w; // w ∈ {0,1}
        if (dist[v] > dist[u] + w) {
            dist[v] = dist[u] + w;
            if (w == 0) dq.offerFirst(v);
            else dq.offerLast(v);
        }
    }
}
```

#### 正确性直觉

双端队列维持了一个弱化版的优先队列：队首始终是当前最小或近似最小的距离层。因为边权只有 0/1，新的距离要么等于当前层，要么进入下一层，用 deque 就足够表达这个顺序，复杂度从 Dijkstra 的 `logV` 降到 `O(V+E)`。

### 3.3 Dijkstra：非负边权的单源最短路王者

#### 适用条件

- 所有边权非负。
- 单源最短路，尤其适合稀疏图。

#### 核心思想

每次从优先队列中取出当前 `dist` 最小的节点 `u`。在**非负边权**前提下，`u` 的最短距离已经最终确定，因为任何绕路都只会增加或不减少代价，不可能再找到一条更短路径回到 `u`。

```java
PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
Arrays.fill(dist, INF);
dist[s] = 0;
pq.offer(new int[]{s, 0});
while (!pq.isEmpty()) {
    int[] cur = pq.poll();
    int u = cur[0], d = cur[1];
    if (d != dist[u]) continue; // 跳过过期节点（懒删除）
    for (Edge e : graph[u]) {
        int v = e.to, w = e.w;
        if (dist[v] > dist[u] + w) {
            dist[v] = dist[u] + w;
            pq.offer(new int[]{v, dist[v]});
        }
    }
}
```

#### 为什么 Dijkstra 不能处理负权？

Dijkstra 的核心假设是：**当前最小的 `dist[u]` 一旦出队，就不会再被改小**。负边会破坏这个假设。

例如：`s→a=2`，`s→b=5`，`b→a=-10`。Dijkstra 可能先确定 `a=2`，但随后通过 `b` 可以得到 `a=-5`，已经确定的点被推翻，算法正确性失效。

#### 变体：瓶颈式 Dijkstra

某些题不是求路径边权和最小，而是求路径上的最大边最小：

```text
dist[v] = min(dist[v], max(dist[u], w(u,v)))
```

代表题：LC 1631 最小体力消耗路径、LC 778 水位上升的泳池中游泳。这类题仍可用 Dijkstra，因为"路径代价"依然随路径延长单调不减。

#### 变体：乘法式 Dijkstra

概率最大路径中，边权是成功概率，路径概率是乘积：

```text
prob[v] = max(prob[v], prob[u] * p(u,v))
```

使用大根堆即可。代表题：LC 1514 概率最大的路径。

### 3.4 Bellman-Ford：负权边的稳定解法

#### 适用条件

- 图中可能存在负权边。
- 不存在从源点可达的负权回路。
- 需要检测负环时也使用它。

#### 核心思想

最短路径如果不含负环，最多经过 `V-1` 条边。因此，对所有边进行 `V-1` 轮松弛，就能保证所有最短路径都被逐步传播到。

```java
Arrays.fill(dist, INF);
dist[s] = 0;
for (int i = 1; i <= n - 1; i++) {
    boolean changed = false;
    for (int[] e : edges) {
        int u = e[0], v = e[1], w = e[2];
        if (dist[u] != INF && dist[v] > dist[u] + w) {
            dist[v] = dist[u] + w;
            changed = true;
        }
    }
    if (!changed) break; // 提前收敛
}
```

第 `V` 轮若还能松弛，则存在负环。

#### 正确性直觉

第 1 轮后，所有使用至多 1 条边的最短路径正确；第 2 轮后，所有使用至多 2 条边的最短路径正确；……第 `V-1` 轮后，所有简单路径都覆盖了。

### 3.5 SPFA：队列优化版 Bellman-Ford

#### 核心思想

Bellman-Ford 每轮扫描所有边，很多边其实没有必要。SPFA 只把**距离刚刚变小的点**入队，因为只有这些点的出边才可能继续引发松弛。

```text
若 dist[u] 变小，则 u 入队；
出队 u，尝试松弛 u 的所有出边；
若 dist[v] 变小且 v 不在队列中，则 v 入队。
```

#### 使用提醒

SPFA 在很多稀疏图上很快，常被认为平均 `O(E)`，但最坏复杂度仍是 `O(VE)`，且容易被构造数据卡死。工程和竞赛中：

- 有负权、规模不大 → Bellman-Ford 更稳定。
- 边权非负 → 不要用 SPFA，直接 Dijkstra。
- 需要负环检测 → SPFA 可维护入队次数，某点超过 `V` 次说明存在负环。

### 3.6 Floyd-Warshall：全源最短路的三重循环

#### 适用条件

- 要查询任意两点间最短路。
- 点数较小，通常 `n ≤ 400` 左右视语言和时限而定。
- 可处理负权边，但不能有负环。

#### 核心思想

`dist[i][j]` 表示当前允许使用某些中转点时，`i` 到 `j` 的最短距离。逐步枚举中转点 `k`：

```java
for (int k = 0; k < n; k++) {
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);
        }
    }
}
```

#### 为什么 k 必须在最外层？

Floyd 的 DP 含义是：允许使用编号 `0..k` 的点作为中转时的最短路。每一轮 `k` 都是在上一轮"只允许 `0..k-1` 作为中转"的基础上，决定是否经过 `k`。如果把 `k` 放内层，这个阶段语义会被破坏。

### 3.7 Johnson：稀疏图全源最短路 + 负边

#### 适用条件

- 需要全源最短路。
- 图稀疏。
- 存在负边但无负环。

#### 核心思想

Johnson 的目标是：**把有负边的图重标权成非负图，然后对每个源点跑 Dijkstra。**

步骤：

1. 新增超级源点 `S`，向所有点连一条权重 0 的边。
2. 从 `S` 跑 Bellman-Ford，得到势能函数 `h[v]`。
3. 对每条边重新赋权：

```text
w'(u,v) = w(u,v) + h[u] - h[v]
```

可证明 `w'(u,v) ≥ 0`。

4. 在新权图上对每个点跑 Dijkstra。
5. 把距离还原：

```text
dist(u,v) = dist'(u,v) - h[u] + h[v]
```

这套重标权不会改变路径之间的相对大小，因为一条路径上的势能项会望远镜式抵消。

### 3.8 DAG 最短路：拓扑序上的动态规划

#### 适用条件

- 图是有向无环图（DAG）。
- 可以有负权，因为无环不会出现负环。

#### 核心思想

按拓扑序处理点。一个点被处理时，所有可能通向它的前驱都已经处理完，因此它的 `dist` 已经稳定，可以直接松弛出边。

复杂度 `O(V+E)`，比 Dijkstra 更快。

### 3.9 A*：带启发函数的单点对搜索

#### 适用条件

- 只关心从 `s` 到 `t` 的一条最短路。
- 能设计一个不高估真实距离的启发函数 `h(x)`。

A* 按：

```text
f(x) = g(x) + h(x)
```

排序，其中 `g(x)` 是从起点到 `x` 的已知代价，`h(x)` 是从 `x` 到终点的估计代价。若 `h` 从不高估真实最短距离（admissible），A* 能保证最优；若 `h` 越接近真实距离，搜索范围越小。

网格地图常用曼哈顿距离 / 欧氏距离作为启发函数。

## 四、题型分类与实战规律总结（核心重点）

这一章是全文落脚点。目标只有一个：**建立"看到题目就能识别最短路模型，并知道该用哪种最短路算法"的直觉。**

### 4.0 先建立"最短路信号"雷达

出现以下信号，请立刻联想到最短路径：

- 🎯 从一个状态到另一个状态，求**最小代价 / 最少步数 / 最短时间 / 最小费用**。
- 🎯 有若干状态，每次操作会从一个状态转移到另一个状态，且操作有代价。
- 🎯 题目中出现"网络延迟""航班中转""钥匙开锁""网格路径""阈值距离"。
- 🎯 有"最多 K 次""是否使用优惠""钥匙集合"等限制，需要把限制扩进状态。
- 🎯 多个点之间反复查询可达性 / 距离。

### 4.1 题型 I：标准单源最短路

- **题眼**：给定边列表、源点，求源点到所有点或某个终点的最短距离。
- **建模**：直接建邻接表，按边权选择 BFS / Dijkstra / Bellman-Ford。
- **代表题**：
  - **LC 743 网络延迟时间**：从源点出发，所有节点收到信号的最晚时间 = 单源最短路后取最大 `dist`。
  - **LC 2662**：特殊道路最短路，通常将关键点建图后 Dijkstra。

**模板判断**：

```text
边权非负 → Dijkstra
边权为 1 / 无权 → BFS
边权含负 → Bellman-Ford / SPFA
```

### 4.2 题型 II：Dijkstra 变形 —— 聚合函数变了

有些题仍是 Dijkstra，但路径代价不再是简单求和。

#### ① 概率最大路径

- **题眼**：最大成功概率、路径概率为边概率乘积。
- **转移**：`prob[v] = max(prob[v], prob[u] * p)`。
- **堆**：大根堆按概率。
- **代表题**：LC 1514 概率最大的路径。

#### ② 瓶颈路径最小化

- **题眼**：最小化路径上的最大边、最小体力、水位上升。
- **转移**：`dist[v] = min(dist[v], max(dist[u], w))`。
- **代表题**：LC 1631 最小体力消耗路径、LC 778 水位上升的泳池中游泳。

#### ③ 最大化路径最小值

- **题眼**：路径得分由最小节点 / 最小边决定，要求最大化。
- **思路**：大根堆，每次扩展当前得分最高状态。
- **代表题**：LC 1102 得分最高的路径。

### 4.3 题型 III：多源 / 全源最短路径

- **题眼**：任意两点、每个城市到其他城市、先求所有可达关系。
- **算法选择**：
  - 点数小：Floyd。
  - 点数大、边权非负：每个点 Dijkstra。
  - 稀疏图 + 负边：Johnson。
- **代表题**：
  - **LC 1334 阈值距离内邻居最少的城市**：可用 Floyd 求任意两点距离，再统计每个城市阈值内邻居数。
  - **LC 1462 课程表 IV**：本质是传递闭包，可用 Floyd 的布尔版本。
  - **LC 3015**：多源/多点对距离统计。

### 4.4 题型 IV：分层图最短路 —— 位置 + 状态的组合

这是最短路题里最重要的进阶模型。

#### 核心思想

当题目中的路径不仅由"当前位置"决定，还由某些额外资源决定时，必须把这些资源扩进节点：

```text
原节点: city
扩展节点: (city, usedCoupons)
扩展节点: (city, stops)
扩展节点: (x, y, keysMask)
扩展节点: (node, timeParity)
```

这叫**分层图**或**状态扩点**。边仍然是状态之间的转移。

#### 常见状态维度

| 附加限制 | 状态扩展 | 代表题 |
|---|---|---|
| 最多 K 站中转 | `(城市, 已用中转数)` | LC 787 |
| 可使用若干次折扣/优惠 | `(城市, 已用优惠次数)` | LC 2093 |
| 有时间限制和费用 | `(城市, 已花时间)` | LC 1928 |
| 钥匙开锁 | `(x, y, keysMask)` | LC 864 |
| 红绿灯 / 第二短路 | `(节点, 第几次到达)` 或维护两个距离 | LC 2045 |

#### 代表题

- **LC 787 K 站中转内最便宜的航班**：状态是 `(city, stops)`，不能只记录城市最短费用，因为到同一城市时"剩余中转次数"不同，后续可行性不同。
- **LC 2093 前往目标城市的最小费用**：可使用折扣，状态是 `(city, discountUsed)`。
- **LC 864 获取所有钥匙的最短路径**：状态是 `(x, y, keysMask)`，边权为 1，因此用 BFS。
- **LCP 35**：通常也是状态扩展型最短路。

> 🎯 **建模口诀**：如果到达同一个位置时，"未来可走的路"会因为某个资源不同而不同，那么这个资源必须放进状态。否则 dist 会错误合并不等价状态。

### 4.5 题型 V：网格最短路

- **题眼**：二维网格中从某格走到某格，求最少步数 / 最小代价 / 最小体力。
- **建模**：点是 `(r,c)`，边是四方向移动。
- **算法选择**：
  - 每步代价相同 → BFS。
  - 代价为 0/1 → 0-1 BFS。
  - 非负代价 → Dijkstra。
  - 瓶颈代价 → 瓶颈式 Dijkstra。

**代表题**：

- LC 1162 地图分析：多源 BFS，从所有陆地同时出发。
- LC 1631 最小体力消耗路径：瓶颈式 Dijkstra。
- LC 407 接雨水 II：边界作为多源，小根堆扩展最低围墙。

### 4.6 题型 VI：第二短路 / 路径计数

#### 第二短路

- **题眼**：第二短时间、次短路径。
- **建模**：对每个点维护两个距离：最短 `dist1[u]` 与次短 `dist2[u]`。
- **代表题**：LC 2045 到达目的地的第二短时间。注意还叠加红绿灯等待逻辑。

#### 最短路条数

- **题眼**：最短路径有多少条。
- **建模**：Dijkstra 同时维护 `ways[u]`。

```text
若发现更短路径：dist[v] = nd, ways[v] = ways[u]
若发现等长路径：ways[v] += ways[u]
```

- **代表题**：LC 1976 到达目的地的方案数。

### 4.7 题型 VII：DAG 最短路 / 拓扑序 DP

- **题眼**：有向无环图、依赖关系、拓扑顺序。
- **算法**：拓扑排序后按序松弛。
- **优势**：`O(V+E)`，支持负权，因为无环。

### 4.8 题型 VIII：A* / 启发式搜索

- **题眼**：地图寻路、只关心单点对、状态空间巨大。
- **算法**：优先扩展 `f=g+h` 最小的状态。
- **关键**：启发函数 `h` 不能高估真实距离，否则可能失去最优性。

## 五、建模速查表与思维导图

### 5.1 最短路径算法选择速查表 ⭐

| 场景 | 边权 / 图结构 | 推荐算法 | 复杂度 | 代表题 |
|---|---|---|---:|---|
| 无权最短步数 | 边权相同 | BFS | `O(V+E)` | 网格最少步数、LC864 |
| 0/1 代价 | 权重 `{0,1}` | 0-1 BFS | `O(V+E)` | 障碍代价 0/1 类题 |
| 非负权单源 | `w ≥ 0` | Dijkstra | `O((V+E)logV)` | LC743、LC2662 |
| 瓶颈路径 | 路径代价为最大边/最小点 | Dijkstra 变形 | `O(ElogV)` | LC1631、LC778、LC1102 |
| 概率最大 | 路径代价为概率乘积 | 大根堆 Dijkstra | `O(ElogV)` | LC1514 |
| 有负边无负环 | `w` 可负 | Bellman-Ford / SPFA | `O(VE)` | 负权单源 |
| 全源小图 | 任意权，点数小 | Floyd | `O(V^3)` | LC1334、LC1462 |
| 稀疏全源 + 负边 | 有负边无负环 | Johnson | `O(VE+V(E+V)logV)` | 稀疏 APSP |
| DAG | 有向无环 | 拓扑序 DP | `O(V+E)` | DAG 最短路 |
| 状态受资源限制 | 位置 + 状态 | 分层图最短路 | 看状态数 | LC787、LC2093、LC864 |
| 单点对 + 地图 | 可设计启发函数 | A* | 依赖启发式 | 游戏/地图寻路 |

### 5.2 题型建模速查表

| 题型分类 | 常见关键词（题眼） | 状态设计 | 算法 |
|---|---|---|---|
| 标准单源 | 网络延迟、从源点到所有点 | `node` | Dijkstra / BFS / Bellman-Ford |
| 网格最短路 | 从起点到终点、四方向移动 | `(r,c)` | BFS / 0-1 BFS / Dijkstra |
| 瓶颈路径 | 最小化最大体力/水位 | `node`，代价聚合为 `max` | Dijkstra 变形 |
| 概率最大 | 成功概率最大 | `node`，代价聚合为乘积 | 大根堆 Dijkstra |
| 阈值统计 | 每点到其他点距离 | `dist[i][j]` | Floyd / 多次 Dijkstra |
| K 次限制 | K 站中转、折扣次数 | `(node,k)` | 分层图 Dijkstra / DP |
| 钥匙集合 | 拿钥匙开锁 | `(r,c,mask)` | BFS / Dijkstra |
| 第二短路 | 第二短时间 | `dist1, dist2` | 改造 Dijkstra / BFS |
| 最短路计数 | 方案数 | `dist + ways` | Dijkstra + 计数 |

```text
                         【最短路径 Shortest Path】
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        │                          │                          │
   ① 建模哲学                 ② 算法选择                  ③ 核心语言
   点 = 状态                   无权 → BFS                  松弛 relax:
   边 = 操作                   0/1 → 0-1 BFS               dist[v] > dist[u]+w
   权 = 代价                   非负 → Dijkstra             就更新
   限制要扩进状态              负权 → Bellman/SPFA          差异在松弛顺序
   单源/全源/单点对             全源小图 → Floyd             与确定性条件
        │                      DAG → Topo DP
        │                      单点对 → A*
        │
        └────────────── ④ 题型（看到就想到最短路）──────────────┐
                                                                │
   标准单源 ─────── "网络延迟/源点到所有点"       → Dijkstra/BFS
   网格路径 ─────── "四方向移动/最少步数"         → BFS/0-1/Dijkstra
   瓶颈路径 ─────── "最大边最小/水位/体力"        → Dijkstra max 聚合
   概率最大 ─────── "概率乘积最大"                → 大根堆 Dijkstra
   全源统计 ─────── "任意两点/阈值邻居"           → Floyd/多次 Dijkstra
   分层图 ───────── "K次/优惠/钥匙/状态资源"      → (位置,状态) 扩点
   第二短/计数 ──── "次短/方案数"                → dist1+dist2 / ways
```

### 5.4 一图流决策：拿到题该怎么选算法？

```text
先问：节点状态是否只由位置决定？
  ├─ 否 → 把额外资源扩进状态：(位置, 状态)
  └─ 是 ↓

再问：边权是什么？
  ├─ 无权/等权 → BFS
  ├─ 0/1 → 0-1 BFS
  ├─ 非负 → Dijkstra
  ├─ 有负权无负环 → Bellman-Ford / SPFA
  └─ DAG → 拓扑序 DP

再问：查几个源？
  ├─ 单源 → 上述单源算法
  ├─ 全源且 n 小 → Floyd
  ├─ 全源且稀疏非负 → 多次 Dijkstra
  └─ 全源且稀疏有负边 → Johnson

最后问：路径代价是否是普通求和？
  ├─ 是 → 标准最短路
  ├─ 最大边最小 → 瓶颈式 Dijkstra
  ├─ 概率乘积最大 → 大根堆 Dijkstra
  └─ 第二短/计数 → 维护额外 dist2 / ways
```

## 六、尾声：一句话记忆锚点

把全文浓缩成三句话，帮你在考场和工程现场瞬间召回：

> 🎯 **建模锚点**：最短路不是只在"地图"上跑，任何题只要能抽象成"状态 + 操作 + 代价"，就是在图上找最短路径；额外限制会影响未来选择时，就必须扩进状态。

> 🎯 **算法锚点**：**无权 BFS，0/1 用双端队列，非负 Dijkstra，负权 Bellman-Ford/SPFA，全源小图 Floyd，DAG 拓扑 DP，状态受限就分层图。**

> 🎯 **本质锚点**：所有最短路算法都在做同一件事——**松弛**。区别只在于谁先松弛、松弛几轮，以及什么时候敢说"这个点的答案已经确定"。
