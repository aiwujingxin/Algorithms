> - **第一部分:导航** — 按策略本质分类的精选题单
> - **第二部分:模板** — 6 大通用代码范式 (The 6 Pillars)
>
> **解题三步法**
> 1. **观察问题结构**:分析是否存在「局部最优决策可推导全局最优」的性质。
> 2. **设计贪心策略**:确定每一步的选择规则 (最小/最大、配对、反悔等)。
> 3. **验证策略正确性**:通过交换论证法或反证法,确保不破坏全局最优。

## I. 价值优先型

### 静态极值

**策略**:基于当前固定的状态 (排序后的数组),每次直接选择最有利的元素 (最大/最小/最匹配),不涉及动态更新集合。 **本质**:
利用单调性或排序不等式,通过一次遍历或双指针,将资源分配给最能产生价值的目标。

- **LeetCode455** 分发饼干
- **LeetCode860** 柠檬水找零 (优先找零大面额)
- **LeetCode605** 种花问题 (防御式贪心)
- **LeetCode1402** 做菜顺序
- **LeetCode870** 优势洗牌 (田忌赛马)
- **LeetCode1899** 合并若干三元组以形成目标三元组

### 动态极值

**策略**:在算法过程中维护一个动态集合 (堆),随着操作进行,集合内容发生变化,每次操作依赖于当前集合的极值。 **本质**:
通过堆结构实时捕获系统演化过程中的"最值",确保每一步操作都是在当前约束下的最优解。

- **LeetCode2182** 构造限制重复的字符串
- **LeetCode1962** 移除石子使总数最小
- **LeetCode767** 重构字符串 (隔板法)
- **LeetCode2233** K 次增加后的最大乘积
- **LeetCode2856** 删除数对后的最小数组长度 (堆模拟/数学)
- **LeetCode1167** 连接棒材的最低费用 (哈夫曼编码)

### Dijkstra / 瓶颈优先

**策略**:系统处于受限状态,利用堆时刻抓住当前最紧的那个约束 (瓶颈/短板),优先处理它。 **本质**:
短板决定论。一旦解决或利用了当前的短板,系统边界就会向更有利的方向演化 (水位上升、路径延伸、资本增加)。

- **Dijkstra**
- **LeetCode407** 接雨水 II
- **LeetCode502** IPO
- **LeetCode778** 水位上升的泳池中游泳
- **LeetCode1631** 最小体力消耗路径
- **LeetCode1102** 得分最高的路径
- **LeetCode1514_Dij** 概率最大的路径

### Prim

**策略**:从一个节点开始,每次选择连接已选集合与未选集合的最小权值边进行扩展。 **本质**:局部最优连接导致全局最小生成树,是
Dijkstra 在无向图连通性上的特例。

- **Prim**

## II. 区间问题

### 活动选择 / 不重叠

**策略**:按结束时间排序,优先选择结束最早的区间,为后面留出更多空间。 **本质**:最大化资源利用率,通过腾出时间槽来容纳更多活动。
**证明**:交换论证法——若不选最早结束的,换成它不会更差。 **注意**:端点相等是否算重叠因题而异 (435:`>=` 不算 | 452:`>`
才算新组 | 646:`>` 严格不相交)

- **MaxActivity** 活动选择 (最大)不重叠
- **LeetCode435** 无重叠区间 (答案 = n - 最多不重叠数; 端点相等不重叠)
- **LeetCode646** 最长数对链 (等价于活动选择; 严格 b < c)
- **LeetCode452** 用最少数量的箭引爆气球 (435 的互补: 端点相等算重叠)

### 分组 / 会议室

**策略**:按开始时间排序,利用堆维护当前所有组的结束时间,尝试复用最早结束的那一组。 **本质**:资源的复用与分配,通过紧凑排列减少资源
(会议室/组)的闲置间隙。 **等价视角**:最少组数 = 最大重叠深度 (扫描线求峰值)。

- **LeetCode253** 会议室 II
- **LeetCode2406** 将区间分为最少组数 (差分/扫描线)

### 覆盖 / 合并

**策略**:按开始时间排序,尽可能延长当前区间的覆盖范围 (右边界),直到断开。 **本质**:连通性合并,通过贪心延伸右边界来减少所需的区间数量或合并碎片。
**关键区分**:

- 合并型: `maxEnd = max(maxEnd, r)`,始终更新 → 求连通分量
- 选择型: `end = r`,仅选中时更新 → 求最多不重叠

- **MinCover** 区间覆盖 (最少)覆盖
- **LeetCode56** 合并区间 (基础模板)
- **LeetCode2580** 统计将重叠区间合并成组的方案数 (连通分量 + 2^k)
- **LeetCode1288** 删除被覆盖区间 (被完全包含则删除)
- **LeetCode1326** 灌溉花园的最少水龙头数目 (跳跃游戏变种)
- **LeetCode757** 设置交集大小至少为 2

### 区间 + 堆 (带截止时间的调度)

**策略**:按开始时间扫描,将所有可选任务放入堆中,优先处理截止时间最早的任务 (EDF 算法)。 **本质**:
在时间流逝的硬约束下,通过优先满足最紧迫的需求来最大化收益。

- **LeetCode1353** 最多可以参加的会议数目 (按开始时间排序,堆维护结束时间)
- **LeetCode1705** 吃苹果的最大数目
- **LeetCode2589** 完成所有任务的最少时间

### 补丁 / 构造连续值 (子集和覆盖模型)

**策略**:维护 reach 表示当前可构造 [0, reach) 的所有整数,排序后逐个吸收或补丁。 **本质**:利用"已有范围 + 新元素 =
扩展范围"的累加性质,指数级扩展覆盖。 **关键**:补 reach 本身可实现翻倍增长 (最优性由 v ≤ reach 的约束推出)。
> ⚠️ **陷阱**:reach 必须用 `long`(n 最大 2^31-1,翻倍会溢出 int)。

- **LeetCode330** 按要求补齐数组 (缺啥补啥,补 reach 翻倍; ⚠️ long 溢出)
- **LeetCode1798** 构造连续值的最大数目 (330 的只读版: 断档即停)
- **LeetCode2952** 需要添加的硬币的最小数目 (330 同族: 输入未排序)

> **330 vs 1798**:同卵双胞胎,数学 100% 等价。差异仅在遇到断档时:1798 停止 / 330 补丁 (补 reach 本身,翻倍)。

## III. 贪心构造

### 字典序

**策略**:从高位到低位,在满足约束的前提下,尽可能填入更小 (或更大)的字符/数字。 **本质**:高位权重大于低位权重之和,利用位权差异进行贪心决策。

- **LeetCode31** 下一个排列
- **LeetCode670** 最大交换
- **LeetCode2375** 根据模式串构造最小数字
- **LeetCode3216** 交换后字典序最小的字符串

### 回文串

**策略**:优先构造回文串的两侧 (高位),将出现次数最多的字符放在外侧,奇数次字符放中间。 **本质**:
利用回文的对称性,将构造问题转化为一般的字典序贪心或频率统计问题。

- **LeetCode564** 寻找最近的回文数
- **LeetCode2384** 最大回文数字
- **LeetCode266** 回文排列

### 双向扫描

**策略**:将复杂约束分解为左规则和右规则,分别进行两次线性扫描,最后取交集 (max)。 **本质**:解耦依赖关系,将双向约束转化为两个独立的单向约束问题。

- **LeetCode135** 分发糖果 (既要又要)
- **LeetCode955** 删列造序 II

### 单调栈 (保留字典序最小/最大)

**策略**:维护一个单调序列,当新元素破坏单调性且仍有删除额度时,果断删除栈顶元素 (反悔)。 **本质**:
通过局部删除逆序对,保证留下的序列在整体上具有最优的字典序结构。

- **MonotonicStack**
- **LeetCode402** 移掉 K 位数字
- **LeetCode316** 去除重复字母 (= 1081 不同字符的最小子序列)
- **LeetCode321** 拼接最大数

### 括号与计数

**策略**:维护一个可能的平衡值区间 [min, max],利用贪心缩放区间范围。 **本质**:利用括号匹配的抵消性质,将匹配问题转化为数值区间的可行性判定。

- **LeetCode678** 有效的括号字符串 (维护区间 [min, max])
- **LeetCode921** 使括号有效的最少添加
- **LeetCode1963** 使字符串平衡的最小交换次数

## IV. 跳跃游戏 (覆盖模型)

**策略**:维护当前能到达的最远距离 (max_reach),在当前覆盖范围内寻找下一步能跳得更远的落脚点。 **本质**:
通过不断拓展"可达边界",用最少的步数覆盖到终点。隐式 BFS 层序遍历。 **统一视角**:45/1024 同构 (点+跳力 = 显式线段)
,330/1798/2952 同族 (子集和覆盖)。

- **LeetCode1326** 灌溉花园的最少水龙头数目 (1024 同构)
- **LeetCode134** 加油站 (环形贪心: total≥0 有解, tank<0 重置起点)
- **LeetCode2952** 需要添加的硬币的最小数目 (补丁型跳跃)
- **LeetCode1306** 跳跃游戏 III (BFS/DFS,非贪心)
- **LeetCode1696** 跳跃游戏 VI (单调队列优化 DP)

## V. 反悔贪心 (堆维护已选集合)

**策略**:先无脑贪心选择,当遇到约束无法满足时,利用堆找出之前选择中"代价最大/收益最小"的元素进行替换 (反悔)。 **本质**:
时光倒流。允许犯错,通过事后修正 (撤销最差决策)来维持当前的最优状态。

- **LeetCode871** 最低加油次数
- **LeetCode630** 课程表 III
- **LeetCode2813** 子序列最大优雅度
- **LeetCode3049** 标记所有下标的最早秒数 II

| 问题特征             | 推荐模板                              |
|----------------------|---------------------------------------|
| 排序后一次遍历可决策 | 模板 1: 排序 + 线性扫描               |

## 模板 1:排序 + 线性扫描 (Sorting + Linear Scan)

**适用场景**:区间调度、活动选择、静态资源分配、双指针贪心。 **核心思想**:
预处理消除无序性。通过排序将杂乱的数据变得有序,然后通过一次遍历,每次只处理局部最优,从而推导出全局最优。

**关键点**

1. Comparator 的定义是解题的灵魂:选择型 (435/452/646)按右端点升序;覆盖型 (1024/1326)按左端点升序;合并型 (56/2580)按左端点升序。
2. ⚠️ 比较器溢出: 用 `Integer.compare(a,b)` 而非 `a-b`

```java
public int greedyLinearScan(int[][] items) {
    // 1. 预处理:排序 (选择型按结束时间升序; 覆盖/合并型按开始时间升序)
    // ⚠️ 永远用 Integer.compare,避免极端值溢出
    Arrays.sort(items, (a, b) -> Integer.compare(a[1], b[1]));

    int count = 0;
    int lastEnd = Integer.MIN_VALUE;

    for (int[] item : items) {
        int start = item[0];
        int end = item[1];

        // 435: start >= lastEnd (端点相等不算重叠)
        // 452: start > lastEnd  (端点相等算重叠)
        // 646: start > lastEnd  (严格大于才可链接)
        if (start >= lastEnd) {
            count++;
            // 选择型: lastEnd = end; 合并型: lastEnd = Math.max(lastEnd, end)
            lastEnd = end;
        }
    }
    return count;
}
```

## 模板 2:堆维护 / 反悔贪心 (Heap / Regret Greedy)

**适用场景**:动态数据流、带截止时间的调度、移除 K 个元素求极值、允许"反悔"的场景。 **核心思想**:
维护一个"当前最优集合"。当新元素破坏约束时,利用堆找出集合里"最差"的元素并牺牲掉,以保全大局。

**反悔贪心 vs 普通堆贪心**:普通堆贪心每次从堆中取最优不可撤回 (Dijkstra, Prim);反悔贪心先贪心选择,发现不行再从堆中淘汰最差的
(630, 871, 2813)。

```java
public int greedyWithHeap(int[][] tasks, int limit) {
    // 1. 按截止时间/开始时间排序
    Arrays.sort(tasks, (a, b) -> Integer.compare(a[0], b[0]));

    // 求最大收益 → 小顶堆; 求最小代价 → 大顶堆
    PriorityQueue<Integer> pq = new PriorityQueue<>((a, b) -> b - a); // 大顶堆
    long currentTotalCost = 0;

    for (int[] task : tasks) {
        int cost = task[1];

        // 先无脑贪心:尝试接纳
        currentTotalCost += cost;
        pq.offer(cost);

        // 约束检查与反悔 (Regret):扔掉堆顶最差的
        while (currentTotalCost > limit && !pq.isEmpty()) {
            currentTotalCost -= pq.poll();
        }
    }
    return pq.size();
}
```

## 模板 3:瓶颈优先 / 广义 Dijkstra (Bottleneck / Best-First)

**适用场景**:接雨水 II、最小体力消耗路径、水位上升游泳、带权重的网格搜索。 **核心思想**:
短板决定论。系统受限于当前的"短板"。优先处理短板,一旦解决或利用了短板,系统边界才会向更有利方向演化。

**与标准 Dijkstra 的区别**:标准 `dist[v] = dist[u] + w`(累加);瓶颈路径 `dist[v] = max(dist[u], w)`(取 max);接雨水 II
水位由围墙最低点决定 (取 max)。

```java
public int greedyBottleneck(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
    boolean[][] visited = new boolean[m][n];

    // 初始化:将起始边界入堆 (如最外圈、起点)

    int currentMax = 0;
    int result = 0;
    int[][] dirs = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int val = curr[0], r = curr[1], c = curr[2];

        currentMax = Math.max(currentMax, val); // 更新瓶颈:木桶效应

        for (int[] dir : dirs) {
            int nr = r + dir[0], nc = c + dir[1];
            if (nr >= 0 && nr < m && nc >= 0 && nc < n && !visited[nr][nc]) {
                visited[nr][nc] = true;
                if (grid[nr][nc] < currentMax) {
                    result += (currentMax - grid[nr][nc]); // 接雨水
                }
                pq.offer(new int[]{grid[nr][nc], nr, nc});
            }
        }
    }
    return result;
}
```

## 模板 4:单调栈贪心 (Monotonic Stack)

**适用场景**:移掉 K 位数字、拼接最大数、去除重复字母、保留相对顺序的字典序问题。 **核心思想**:
维护一个"完美序列"。当新元素比栈顶"更优"且还有"作弊额度"(k > 0)时,踢走栈顶让新元素上位。

**关键点**:栈内保持单调性;额度约束防止过度删除;扫尾时额度没用完就删尾部 (已单调)。

```java
public String greedyMonotonicStack(String s, int k) {
    Deque<Character> stack = new ArrayDeque<>();

    for (char c : s.toCharArray()) {
        // 栈顶劣于当前 && 还有删除额度
        while (!stack.isEmpty() && k > 0 && stack.peekLast() > c) {
            stack.pollLast();
            k--;
        }
        stack.addLast(c);
    }

    // 扫尾:额度没用完,栈内已单调递增,删尾部
    while (k > 0) {
        stack.pollLast();
        k--;
    }

    StringBuilder sb = new StringBuilder();
    while (!stack.isEmpty()) {
        sb.append(stack.pollFirst());
    }
    return sb.toString();
}
```

## 模板 5:区间覆盖 / 跳跃延伸 (Coverage Extension / Implicit BFS)

**适用场景**:跳跃游戏、视频拼接、灌溉花园、区间覆盖最小数量。 **核心思想**:
在当前能力极限范围内,寻找下一步能跳得更远的跳板,不断更新"当前能到达的最远边界"。

**关键点**:隐式 BFS (每次跳跃 = 一层扩展);三变量 end/maxPosition/steps;⚠️ 遍历到 n-2 而非 n-1;45/1024/1326 同构差异仅在预处理。

```java
public int greedyJump(int[] nums) {
    int end = 0;         // 当前层右边界
    int maxPosition = 0; // 下一层能到达的最远位置
    int steps = 0;

    // ⚠️ 遍历到 n-2:到了 n-1 就不需要再跳了
    for (int i = 0; i < nums.length - 1; i++) {
        maxPosition = Math.max(maxPosition, i + nums[i]); // 探测最远

        if (i == end) { // 到达当前层边界:必须跳了
            end = maxPosition;
            steps++;
            if (end >= nums.length - 1) break; // 剪枝:已覆盖终点
        }
    }
    return steps;
}
```

## 模板 6:补丁型贪心 / 子集和覆盖 (Patching / Subset-Sum Coverage)

**适用场景**:构造连续值、按要求补齐数组、添加硬币使覆盖 [1, target]。 **核心思想**:维护 reach = 当前可构造的连续值上界 [0,
reach)。遍历排序后的数组,若 `nums[i] <= reach` 则吸收,否则"缺啥补啥"——补 reach 本身,实现覆盖范围翻倍。

**关键点**:补 reach 本身增长率最大;⚠️ reach 必须用 `long`;补丁次数上界 O (log target);330 vs 1798 遇断档 patch vs stop。

```java
public int greedyPatching(int[] nums, int target) {
    Arrays.sort(nums);
    // ⚠️ 必须用 long!target 接近 Integer.MAX_VALUE 时 reach 翻倍会溢出变负 → 死循环
    long reach = 0; // 当前能覆盖 [1, reach]
    int patches = 0;
    int i = 0;

    while (reach < target) {
        if (i < nums.length && nums[i] <= reach + 1) {
            // 吸收: [1, reach] ∪ [nums[i], reach+nums[i]] = [1, reach+nums[i]]
            reach += nums[i];
            i++;
        } else {
            // 补丁: 补 reach+1 最优
            // [1, reach] ∪ [reach+1, 2*reach+1] = [1, 2*reach+1]
            reach += reach + 1; // 等价于 reach = 2*reach + 1
            patches++;
        }
    }
    return patches;

    // 变体 1798 (只读版): 遇到断档直接 break,返回 reach
    // long reach = 1;
    // for (int c : coins) {

    //     reach += c;
    // }
    // return (int) reach;
}
```
