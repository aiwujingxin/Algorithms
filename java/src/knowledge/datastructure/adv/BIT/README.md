# 树状数组：从母模板到灵活变种

树状数组的关键不是记住多少份代码，而是理解：

> 用 `lowbit` 把前缀拆成若干个不重叠的二进制块，并动态维护每个块的聚合信息。

只要问题能转化为“动态维护前缀信息”，就应该想到树状数组；至于求和、计数、最值、第 K 小、二维矩形，本质上只是块中信息和坐标含义发生了变化。

---

## 1. 母模板抓住了什么性质

对于 1-based 下标，定义：

```text
lowbit(x) = x & -x
tree[x] 维护区间 (x - lowbit(x), x]
```

例如：

```text
tree[12] 维护 [9, 12]，因为 lowbit(12) = 4
tree[8]  维护 [1, 8]，因为 lowbit(8) = 8
```

由这个块定义自然得到两条固定路径：

```java
// 单点 x 影响所有包含 x 的祖先块
for (int i = x; i <= n; i += i & -i) {
    tree[i] += delta;
}

// [1, x] 被拆成若干个互不重叠的块
for (int i = x; i > 0; i -= i & -i) {
    ans += tree[i];
}
```

### 永远不变的部分

1. 使用 1-based 下标。
2. `tree[i]` 维护 `(i-lowbit(i), i]`。
3. 更新沿 `i += lowbit(i)` 向祖先传播。
4. 前缀查询沿 `i -= lowbit(i)` 拆分区间。
5. 单次更新和查询通常都是 `O(log n)`。

### 可以变化的部分

1. **坐标含义**：数组位置、离散化后的值、时间、行列坐标。
2. **维护信息**：和、出现次数、异或、最大值、最小值。
3. **更新模型**：单点增加、单点取最大、区间增加。
4. **查询模型**：前缀、区间、排名、第 K 小、二维矩形。
5. **树的数量**：一棵、两棵、二维多棵。

所以，树状数组变种不是重新发明结构，而是：

```text
固定的二进制块骨架 + 不同的代数信息 + 不同的问题映射
```

## 2. 为什么有些信息能维护，有些不能

### 2.1 块内合并必须满足结合律

若一个大区间由多个块组成，合并顺序不应影响答案：

```text
(a ◦ b) ◦ c = a ◦ (b ◦ c)
```

因此求和、计数、异或、最大值、最小值、GCD 都能作为块信息。但结合律只保证“块可以合并”，动态更新还需要可逆性或单调性。

### 2.2 任意区间查询通常还需要“可逆”

基础树状数组通过两个前缀得到区间：

```text
sum(l, r) = prefix(r) - prefix(l - 1)
```

这要求聚合运算存在逆操作：

| 运算 | 前缀可维护 | 能否两个前缀得到任意区间 |
| :--- | :---: | :---: |
| 加法 | 是 | 是，用减法 |
| 异或 | 是 | 是，用异或 |
| 计数 | 是 | 是，用减法 |
| 最大值 | 单调更新时可以 | 否 |
| 最小值 | 单调更新时可以 | 否 |
| GCD | 仅受限更新 | 否 |

这就是为什么前缀最大值容易，而任意区间最大值明显更复杂。

### 2.3 不可逆信息通常需要额外限制

`max` 没有逆运算。若一个点从 10 降为 3，祖先块中的 10 是否仍由其他点贡献，无法只看当前块判断。

因此 [BITreeMax](BITreeMax.java) 和 [BITreeRangeMax](BITreeRangeMax.java) 都抓住了一个额外性质：

> 单点值只能变大，块最大值不会失效。

如果需要任意赋值、值可能减小、区间修改，优先使用线段树。

## 3. 当前包中的六个变种

| 模板 | 坐标含义 | 更新 | 查询 | 推导关键 |
| :--- | :--- | :--- | :--- | :--- |
| [BITree](BITree.java) | 数组位置 | 单点增加 | 前缀和、区间和 | 母模板 |
| [BITreeRange](BITreeRange.java) | 数组位置 | 区间增加 | 前缀和、区间和 | 差分 + 两棵 BIT |
| [BITree2D](BITree2D.java) | 二维坐标 | 单点增加 | 二维前缀和、矩形和 | 一维结构沿两个维度展开 |
| [BITreeKth](BITreeKth.java) | 离散化后的值 | 频率增减 | 排名、第 K 小 | 下标从“位置”变成“值” |
| [BITreeMax](BITreeMax.java) | DP 状态坐标 | 单点取最大 | 前缀最大值 | 加法换成 `max`，更新只能变大 |
| [BITreeRangeMax](BITreeRangeMax.java) | DP 状态坐标 | 单点取最大 | 任意区间最大值 | 原值数组 + Fenwick 块分解 |

### 3.1 基础和：`BITree`

最标准的模型：

```text
单点增加 + 前缀和
区间和 = 右前缀 - 左前缀
```

若题目是“单点赋值”，记录原值并转成增量：

```text
delta = newValue - oldValue
add(index, delta)
```

### 3.2 区间增加、区间和：`BITreeRange`

先把区间增加转成差分数组的两个单点修改：

```text
d[l]     += delta
d[r + 1] -= delta
```

只维护一棵差分 BIT，可以做到“区间增加、单点查询”。

若还要查询原数组前缀和，则推导：

```text
a[i] = Σ d[j]                 (j <= i)
prefix(x) = Σ a[i]            (i <= x)
          = x·Σd[i] - Σ(i-1)·d[i]
```

所以分别维护 `d[i]` 和 `(i-1)d[i]`，得到两棵树状数组。

### 3.3 二维矩形和：`BITree2D`

一维查询路径是：

```text
x -= lowbit(x)
```

二维只是对行列分别执行同样的分解：

```text
for (x ...)
    for (y ...)
```

矩形和再使用二维前缀容斥：

```text
S(r2,c2) - S(r1-1,c2) - S(r2,c1-1) + S(r1-1,c1-1)
```

### 3.4 排名与第 K 小：`BITreeKth`

这是最重要的思维跨越：

```text
普通 BIT：下标表示数组位置，值表示元素和
权值 BIT：下标表示元素值，值表示出现次数
```

于是：

```text
countLE(x) = 值域前缀 [1, x] 的频率和
第 k 小     = 最小的 x，使 countLE(x) >= k
```

由于频率非负，前缀和单调，可以在 Fenwick 树上倍增寻找第 K 小。

### 3.5 前缀最大值：`BITreeMax`

将块聚合从加法替换为最大值：

```text
tree[i] = max(tree[i], value)
```

它适合：

- 最长递增子序列 DP；
- 按坐标排序后的最优状态转移；
- `dp[x] = max(dp[1..x]) + gain`。

限制是单点状态只能变大。

### 3.6 任意区间最大值：`BITreeRangeMax`

最大值不能用两个前缀相减，因此查询 `[l,r]` 时：

1. 保存每个位置的真实值；
2. 从右端向左移动；
3. 能完整放入 `[l,r]` 的 Fenwick 块直接取块最大值；
4. 边界不能整块覆盖的位置单独取值。

这仍要求更新只能变大。若问题没有这个单调性，线段树更自然。

## 4. 看到新题时如何想到树状数组

按下面五个问题依次判断。

### 第一步：查询能否前缀化

典型信号：

- `[1,x]` 的和、数量、最大值；
- `[l,r]` 可以由两个前缀消去；
- 统计“小于等于 x 的元素个数”；
- 动态排名、第 K 小；
- 二维矩形可以做前缀容斥。

### 第二步：是否存在动态修改

没有修改时，普通前缀和、排序、稀疏表可能更简单。

存在单点修改或可差分的区间修改，并要求在线查询时，树状数组才有价值。

### 第三步：坐标轴究竟是什么

不要默认下标一定是原数组位置：

| 问题 | BIT 下标 |
| :--- | :--- |
| 动态区间和 | 数组位置 |
| 逆序对 | 离散化后的值 |
| 动态排名 | 离散化后的值 |
| LIS 优化 | DP 的状态坐标 |
| 扫描线统计 | 另一个维度的坐标 |
| 二维点修改 | 行、列坐标 |

很多树状数组难题，真正难点不是代码，而是找到正确的坐标轴。

### 第四步：聚合运算满足什么性质

```text
有结合律？       -> 可以分块聚合
有逆运算？       -> 可以由两个前缀得到区间
前缀值单调？     -> 可以倍增找第 K 小
更新具有单调性？ -> 可以维护前缀 max/min
```

### 第五步：和线段树比较

| 场景 | 优先选择 |
| :--- | :--- |
| 单点修改 + 前缀/区间和 | 树状数组 |
| 区间加 + 区间和 | 双树状数组 |
| 动态频率、排名、第 K 小 | 权值树状数组 |
| 单调更新 + 前缀最值 | 最值树状数组 |
| 任意区间修改、赋值、最值 | 线段树 |
| 维护复杂节点信息、左右合并有方向 | 线段树 |
| 需要懒标记、多种修改共存 | 线段树 |

一句话：

> 树状数组擅长“前缀可聚合”；线段树擅长“任意区间可合并”。

## 5. 从母模板推导新变种的固定流程

以后不要直接改循环，先写清楚下面七项：

1. **坐标定义**：`i` 表示位置、值还是状态？
2. **节点不变量**：`tree[i]` 具体维护哪个区间、什么信息？
3. **合并运算**：加法、异或、最大值还是自定义状态？
4. **单位元**：0、`Long.MIN_VALUE` 还是其他值？
5. **更新影响**：一次修改会影响哪些祖先块？
6. **查询拆分**：答案如何由若干 Fenwick 块组成？
7. **额外前提**：是否要求可逆、非负频率、单调更新？

只有这七项都明确，代码才应该开始写。

### 正确性证明也固定为三步

1. 证明每个 `tree[i]` 始终满足节点不变量。
2. 证明更新路径覆盖所有受影响块，且不多不少。
3. 证明查询路径把目标区间拆成不重不漏的块。

最后用暴力数组进行随机对拍，重点覆盖：

- `n=1`；
- 左右端点为 1 或 n；
- 重复更新同一点；
- 负数与极值；
- 重复值和离散化边界；
- 第 1 小和最后一小。

## 6. 还可以继续扩展的常见变种

### 建议优先补充

1. **区间增加 + 单点查询**  
   一棵 BIT 维护差分，比 `BITreeRange` 更轻。

2. **异或树状数组**  
   将加减替换为异或，`rangeXor(l,r)=prefix(r)^prefix(l-1)`。

3. **前缀最小值树状数组**  
   与 `BITreeMax` 对称，要求单点值只能变小。

4. **二维区间增加 + 矩形和**  
   二维差分与容斥结合，通常需要四棵二维 BIT。

5. **稀疏树状数组**  
   极大值域且操作点很少时，用哈希表存 Fenwick 节点；能够离散化时仍优先离散化。

### 更高阶的组合变种

1. **扫描线 + BIT**：固定一个维度的顺序，用 BIT 维护另一个维度，解决二维偏序和矩形计数。
2. **CDQ 分治 + BIT**：把三维偏序降成分治顺序加一维动态前缀。
3. **离线询问 + BIT**：按值或端点排序，把条件逐步加入 BIT。
4. **BIT 套有序结构**：支持二维动态排名，但实现和常数明显增大。
5. **可回滚 BIT**：分治递归中记录修改，退出时撤销。

这些高阶变种仍然没有改变 Fenwick 块，只是改变了“何时更新”和“坐标表示什么”。

---

## 7. 常见错误边界

1. 更新下标不能为 0，否则 `i += lowbit(i)` 不会前进。
2. 区间和及带权公式优先使用 `long`，避免乘法溢出。
3. `max/min` 没有逆运算，不能照搬前缀和的区间公式。
4. 权值 BIT 的频率必须保持非负，第 K 小要求 `k` 合法。
5. 离散化必须明确相等元素如何排名，以及查询 `<x` 还是 `<=x`。
6. 前缀最值模板必须确认更新方向具有单调性。
7. 二维 BIT 空间是 `O(nm)`，坐标很大时不能直接开矩阵。
8. 先定义单位元；存在负数时，最大值不能默认初始化为 0。

## 8. 最终抽象

树状数组的所有变种可以压缩成一句公式：

```text
问题答案
= 选择正确的坐标轴
+ 把目标转成前缀
+ 在 lowbit 块中维护满足条件的聚合信息
```

真正需要掌握的不是六份实现，而是三次判断：

1. **能不能前缀化？**
2. **维护的信息是否可结合、可逆或具有单调性？**
3. **下标应该表示位置，还是值、时间、状态或另一个维度？**

一旦这三个问题回答清楚，从基础 `BITree` 推导新变种就不再依赖灵感，而是一个可重复的建模过程。
